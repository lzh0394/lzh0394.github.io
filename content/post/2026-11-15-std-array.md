## 0. 结论摘要

`std::array` 是标准库中最接近内建数组的容器。它是一个聚合类型，唯一的数据成员是 N 个连续存放的元素，`size()` 恒等于模板参数 N，没有分配、没有容量、没有失效。这个定义推出它几乎全部的行为与限制。

- 布局决定了其余性质。`std::array` 在 N 不为 0 时的大小等于 N 乘元素大小，对齐等于元素对齐，`&a[n] == &a[0] + n` 是规范要求。对象内没有间接层，也没有为分配器、容量或调试代理预留的成员。
- 规范身份是连续容器。它满足容器与可逆容器的全部要求，只有两处例外：默认构造的对象在 N 不为 0 时不为空，`swap` 是线性复杂度。序列容器要求只满足一部分，因为没有增长接口。
- 初始化决定正确性。聚合初始化保留内建数组的花括号规则，漏写的元素被值初始化；`std::array<int, 3> a;` 的元素值不确定，`a{}` 才得到全零。CTAD 要求所有实参同型，`to_array` 才提供从内建数组推导长度的路径。
- 与内建数组的差别集中在类型层面：不退化、可赋值、可按值返回、知道自身长度；代价是不能通过初始化列表让编译器数出元素个数，必须显式写出 N，或借助 CTAD 与 `to_array`。
- 使用面的边界同样由标准划定：`at` 抛 `std::out_of_range`，`operator[]` 不检查；比较从 C++20 起由 `operator==` 与 `operator<=>` 承担；`tuple_size`、`tuple_element` 与 `get` 让它参与结构化绑定；`constexpr` 覆盖范围随版本逐步扩大。跨模块传递对象本身只依赖布局，传递迭代器则依赖实现与调试档。

## 1. 范围与口径

`std::array` 的成员函数只有二十余个，行为却由三个层面共同决定：布局层面，元素连续且长度是类型的一部分；类型层面，它是聚合，与内建数组在退化、赋值、传参上不同；接口层面，访问、比较、tuple 接口与 `constexpr` 各自有版本边界。多数误用来自把内建数组的经验直接套到 `std::array`，或者把它当成容量固定的 `vector`。

## 2. 标准要求

### 2.1 规范身份

`std::array` 的规范身份由 `[array.overview]/1` 至 `/3` 给出，三条要求分别是：

- 它是连续容器，存放 N 个 T 类型的元素，`size() == N` 是不变量；连续容器要求给出 `&a[n] == &a[0] + n`。
- 它是聚合，可以用至多 N 个可转换到 T 的初始化器进行列表初始化。
- 它满足容器与可逆容器的全部要求，例外有两条：默认构造的对象在 N 不为 0 时不为空，`swap` 不具备常数复杂度。序列容器要求只满足一部分。

连续容器的要求不在 `[array]` 里，而在 `[container.reqmts]`。这条要求规定迭代器与常迭代器是随机访问迭代器，并建模 `contiguous_iterator`，由此得到 `data()`、指针算术与 C 接口互操作的规范依据。C++17 起 `std::array` 明确满足这条要求，C++11 的文本只写了「支持随机访问迭代器」与连续性恒等式。

`[array.overview]/4` 与 `/5` 是 C++20 增加的补充：`T` 是 structural type 时 `std::array` 也是 structural type，两个数组在每对对应元素都 template-argument-equivalent 时是同一个模板实参；迭代器与常迭代器满足 constexpr 迭代器要求。前者让 `std::array` 能作为非类型模板参数，后者是常量求值中遍历元素的前提。

不提供 `push_back`、`insert`、`erase`、`reserve` 一类接口不是遗漏。序列容器要求中与增长相关的部分对定长存储没有意义，标准因此只要求满足其中一部分。

### 2.2 聚合类型与特殊成员

`[array.cons]/1` 规定，`std::array` 依靠隐式声明的特殊成员函数满足容器要求表；隐式移动构造与移动赋值额外要求 `T` 满足 `Cpp17MoveConstructible` 或 `Cpp17MoveAssignable`。这条规定有几个直接推论：

- 没有用户声明的构造函数，所以它是聚合，花括号初始化直接初始化存储的元素。
- 复制、移动、赋值与析构都逐元素进行，是否平凡由 `T` 决定。`T` 平凡可复制时 `std::array` 也平凡可复制，对象表示可以按字节复制。
- `T` 不可默认构造时，`std::array<T, N> a;` 不合法，因为聚合的默认初始化要求元素可默认构造；写成 `a{...}` 提供全部元素则合法。
- `T` 是引用类型时实例化不合法。容器要求元素是对象类型，MSVC STL 在类内用 `static_assert` 直接给出这条诊断。

### 2.3 复杂度与异常

`std::array` 的操作都不分配，复杂度只由元素操作次数决定：

| 操作 | 复杂度 | 异常 |
| --- | --- | --- |
| 复制、移动、赋值 | 线性于 N | 由 `T` 的对应操作决定 |
| `operator[]`、`front`、`back`、`data` | 常数 | 不抛，声明为 `noexcept` |
| `at` | 常数 | 越界抛 `std::out_of_range` |
| `fill`、`swap`、比较 | 线性于 N | `fill` 由赋值决定，`swap` 由元素交换决定 |
| `size`、`empty`、`max_size` | 常数 | 不抛 |

没有分配，所以没有 `bad_alloc` 这一类失败路径。`swap` 的异常规范是 `noexcept(is_nothrow_swappable_v<T>)`，N 为 0 时规范要求它等价于 `noexcept(true)`（`[array.zero]/3`）。`at` 是唯一按设计抛异常的元素访问函数，它的 `std::out_of_range` 来自 `[sequence.reqmts]` 中 `a.at(n)` 的条目。

### 2.4 零长度特化

`[array.zero]/1` 要求 `std::array` 支持 N 为 0 的情形，`/2` 规定此时 `begin() == end()` 为同一个唯一值，`data()` 的返回值未指定，`/3` 要求 `swap` 的异常规范等价于 `noexcept(true)`。零长度数组仍然是完整类型，有 `size()`、`empty()`、比较与 tuple 接口。

`front()` 与 `back()` 在 N 为 0 时没有可返回的元素。`[sequence.reqmts]` 为这两个成员写了非空的前置条件，违反前置条件在未启用加固时是未定义行为，启用加固后是可诊断的失败（第 12.2 节）。

### 2.5 与内建数组的规范关系

C++11 的 `[array.overview]` 把成员写成 `T elems[N]` 并注明仅供说明，当前草案不再给出成员，只保留连续性与恒等式。标准没有要求 `std::array` 内部真的含有一个 `T[N]` 对象，也没有要求它是标准布局类型。这一点决定了两条边界：

- 元素地址连续、`data()` 返回首元素地址、`&a[n] == &a[0] + n` 都是可以依赖的。
- 把 `std::array` 对象的地址转换成指向 `T[N]` 的指针不在标准的保证内，尽管三家实现都用一个 `T[N]` 成员存放元素。需要 `T[N]` 的接口时，传 `data()` 与长度，或改用 `std::span`。

## 3. 布局与对象模型

### 3.1 唯一数据成员

三家实现的布局一致：对象内只有一个数组成员，没有其他字段。

| 实现 | 数据成员 | 迭代器类型 |
| --- | --- | --- |
| libstdc++ | `_M_elems`，类型为 `__array_traits<T, N>::_Type`，即 `T[N]` | `T*` |
| MSVC STL | `_Elems`，类型为 `T[N]` | `_Array_iterator` 与 `_Array_const_iterator` |
| libc++ | `__elems_`，类型为 `T[N]` | 默认为 `T*`，可由 ABI 宏切换 |

libstdc++ 用 `__array_traits` 把「N 个元素的数组」与「N 为 0 时的占位类型」分开，`std::array` 本身不偏特化；MSVC 与 libc++ 为 N 为 0 提供了 `std::array` 的偏特化。两种写法对外接口相同，差别落在零长度对象的存储方式上。

### 3.2 大小与对齐

N 不为 0 时，`std::array` 的大小等于 N 乘 `sizeof(T)`，对齐等于 `alignof(T)`，没有额外字节。由此可以推出三点：

- 按值传递复制的字节数与内建数组相同，成本由 `T` 的复制成本决定。
- 作为类成员不增加间接层，外层对象的大小随 N 线性增长。
- 大 N 的 `std::array` 放在栈上会占用相应栈空间，与其他栈对象受同一限制。

N 为 0 时大小至少为 1，具体值由实现定义。libstdc++ 用空结构体占位，结果为 1；libc++ 按含一个元素的内部结构体分配空间与对齐，结果等于 `sizeof(T)`；MSVC 在 `T` 可默认构造时用 `T[1]`，否则用空类型，结果等于 `sizeof(T)` 或 1。`std::array<T, 0>` 因此不能当作零大小成员使用，把它放进结构体仍会增加至少一个字节。

### 3.3 N 为 0 时的存储与 data()

`[array.zero]/2` 只规定 `begin() == end()` 为同一唯一值，`data()` 未指定。三家实现都返回空指针 [impl]：libstdc++ 的空类型提供到 `T*` 的显式转换并返回 `nullptr`，MSVC 与 libc++ 的偏特化直接返回 `nullptr`。依赖这一点没有规范依据，判断空数组用 `empty()`。

零长度数组的下标访问没有合法值。libstdc++ 在空类型的 `operator[]` 中直接 trap，MSVC 在加固档或调试档报告错误，libc++ 调用 `__libcpp_unreachable`。这些诊断由实现给出，不改变标准的未定义行为定性。

### 3.4 迭代器类型

`[array.syn]` 把 `iterator` 与 `const_iterator` 写成 implementation-defined，三家给出的类型不同：

- libstdc++ 用 `T*`，`begin()` 直接返回 `data()`。
- MSVC STL 用 `_Array_iterator` 与 `_Array_const_iterator`，保存指针与下标；调试档保存下标并做范围校验，发布档只保留指针。
- libc++ 默认用 `T*`；定义 `_LIBCPP_ABI_BOUNDED_ITERATORS_IN_STD_ARRAY` 时改用 `__static_bounded_iter`，定义 `_LIBCPP_ABI_USE_WRAP_ITER_IN_STD_ARRAY` 时改用 `__wrap_iter`。

由此得到两个推论。其一，`begin()` 的返回类型在 MSVC 上与 `data()` 不同型，把 `&a[0]` 与 `a.begin()` 混用的代码在部分实现上无法通过编译。其二，`std::contiguous_iterator` 在三家实现上都成立，所以 `std::to_address(a.begin())`、`std::span` 与范围算法不依赖具体类型。跨模块传递迭代器的问题放在第 10 章。

## 4. 初始化与类型推导

### 4.1 聚合初始化

`std::array` 的初始化规则与内建数组相同，只是长度由模板参数给出：

```cpp
std::array<int, 4> a{1, 2};            // {1, 2, 0, 0}
std::array<int, 4> b;                  // 元素未初始化
std::array<int, 4> c{};                // 全 0
std::array<int, 4> d{1, 2, 3, 4, 5};   // 错误：初始化器过多
std::array<long, 2> e{1, 2};           // 合法：int 转换到 long
std::array<int, 2> f{1.5};             // 错误：窄化转换
```

规则来自 `[dcl.init.aggr]`：初始化器少于 N 个时，剩余元素被值初始化；初始化器多于 N 个时程序不符合标准。空花括号对聚合做值初始化，每个元素按值初始化规则处理，`int` 元素因此为 0。没有花括号的 `b` 是默认初始化，`int` 元素的值不确定，类类型元素调用默认构造函数。

这条差异是 `std::array` 最常见的错误来源之一。声明 `std::array<int, 4> b;` 之后再读取元素，行为未定义；写成 `b{}` 或 `b = {}` 才会清零，后者用值初始化的临时对象做复制赋值。

### 4.2 花括号的层数

`std::array<int, 3> a{{1, 2, 3}};` 与 `std::array<int, 3> a{1, 2, 3};` 都合法。双层花括号显式初始化唯一的数组成员，单层依赖花括号省略。C++11 的早期文本要求双层，缺陷报告修正后单层可用，C++14 起单层是常规写法。

嵌套数组按层展开：

```cpp
std::array<std::array<int, 2>, 2> m{{{1, 2}, {3, 4}}};
std::array<std::array<int, 2>, 2> n{{1, 2}, {3, 4}};   // 省略一层
```

最外层的花括号可以省略一层，内层每组仍需成对。层数写错时的诊断通常是「初始化器过多」或「无法从花括号初始化列表转换」，指向层数，与元素值无关。

### 4.3 CTAD 与推导指引

C++17 起可以用类模板实参推导省略元素类型与长度。`[array.cons]/2` 给出的推导指引等价于：

```cpp
template<class T, class... U>
array(T, U...) -> array<T, 1 + sizeof...(U)>;
```

该指引的 Mandates 要求 `(is_same_v<T, U> && ...)` 为真，也就是所有实参类型相同。由此得到几条使用边界：

```cpp
std::array a{1, 2, 3};                  // array<int, 3>
std::array b{1, 2.0};                   // 不合法：类型不同
std::array c{"x", "y"};                 // array<const char*, 2>
std::array<std::string, 2> d{"x", "y"}; // 元素类型需要显式指定
```

空列表不能推导，`std::array a{}` 不合法，零长度数组要写成 `std::array<int, 0>{}`。字符串字面量推导出的是指针，需要字符串对象时显式写出元素类型。同型要求由 Mandates 给出，诊断形式由实现决定：libstdc++ 与 libc++ 用 SFINAE 让候选不可行；MSVC 用 `_Enforce_same` 与 `static_assert` 给出文字说明 [impl]。

### 4.4 to_array

C++20 的 `std::to_array`（P0325R4）从内建数组构造 `std::array`，长度由模板参数推导：

```cpp
int raw[] = {1, 2, 3};
auto a = std::to_array(raw);              // array<int, 3>
auto b = std::to_array("abc");            // array<char, 4>，含结尾空字符
auto c = std::to_array(std::move(raw));   // 移动元素
```

`[array.creation]/1` 至 `/6` 规定：左值重载要求 `T` 满足 `Cpp17CopyConstructible`，右值重载要求 `Cpp17MoveConstructible`；返回类型是 `array<remove_cv_t<T>, N>`，元素逐个复制或移动；函数是 `constexpr`。`to_array` 只接受内建数组，不接受 `std::array`，后者直接复制即可。

与 CTAD 的分工：CTAD 从初始化器列表得到类型与长度，`to_array` 从已有的内建数组得到长度并去掉 cv 限定。前者适合字面量初始化，后者适合包装既有的 C 数组或字符串字面量。

## 5. 元素访问与迭代

### 5.1 operator[] 与 at

`operator[]` 不做边界检查，返回引用；`at` 检查 `pos >= size()`，越界抛 `std::out_of_range`（`[sequence.reqmts]` 的 `a.at(n)` 条目）。两者都是常数时间，返回类型与 cv 限定一致。

选择取决于下标来源。下标由容器自身的循环或已知常量给出时用 `operator[]`，热路径上没有分支；下标来自外部输入、协议字段或用户配置时用 `at`，把错误变成可捕获的异常。容器内部已经保证下标有效却仍调用 `at`，是把检查重复做一遍。

`at` 的函数体没有 `noexcept`，在 `noexcept` 函数、析构函数与不期望异常的路径上调用需要外层处理。`operator[]` 在启用加固时也会检查下标，检查方式见第 12.2 节；关闭加固时没有运行时成本。

### 5.2 front、back 与 data

`front()` 返回第一个元素，`back()` 返回第 N 个元素，N 为 0 时两者都没有合法调用。`data()` 返回指向首元素的指针，`[array.members]/2` 要求 `[data(), data() + size())` 是有效范围，非空时 `data() == addressof(front())`。

`data()` 的类型是 `T*` 或 `const T*`，可以直接传给 C 接口。N 为 0 时返回值未指定，解引用是错误；需要判断是否为空时用 `empty()`，不要比较 `data()` 与 `nullptr`。

### 5.3 连续容器与 span

`std::array` 建模 `contiguous_range`，`std::span` 的构造函数接受它，静态长度版本还能在编译期核对长度：

```cpp
std::array<int, 4> a{1, 2, 3, 4};
std::span<int> s(a);          // 长度由 a 推导
std::span<int, 4> t(a);       // 静态长度，长度不匹配则编译失败
const int* p = a.data();
```

`std::size(a)`、`std::ranges::size(a)`、`std::begin(a)` 对 `std::array` 都可用，因为这些设施接受内建数组与满足范围要求的类型。对 `std::array` 使用范围 `for` 与算法时，迭代器就是第 3.4 节的类型，行为由连续容器要求保证。

### 5.4 迭代器与引用的稳定性

`std::array` 没有插入与删除，元素地址在对象生命周期内不变，迭代器与引用不会失效。`swap` 是唯一的例外：它逐个交换元素，迭代器仍与原来的数组关联，交换后通过同一迭代器读到的是对方原来的元素（`[array.members]/5` 的注）。引用与指针在 `swap` 后仍然有效，指向同一位置，值已经改变。

这条规则与 `vector` 的 `swap` 不同。`vector::swap` 交换缓冲区指针，迭代器跟随元素；`array::swap` 交换值，迭代器跟随对象。编写跨容器的泛型代码时，不能假设 `swap` 之后迭代器与元素的对应关系。

## 6. 比较与三路比较

### 6.1 C++20 之前的比较

C++11 起 `std::array` 提供 `==`、`!=`、`<`、`>`、`<=`、`>=` 六个运算符，语义是逐元素相等与字典序比较。C++20 移除了后五个，保留 `==` 并增加 `<=>`，旧写法由重写规则继续可用：`a < b` 被重写为 `(a <=> b) < 0`。

移除与重写改变了重载解析的细节。C++17 的 `a != b` 直接调用 `operator!=`；C++20 的 `a != b` 由 `operator==` 取反得到。对 `std::array` 这样的标准类型，结果一致；对自定义类型，运算符重写可能引入额外的候选，混用 C++17 与 C++20 编译的代码需要注意这一点。

### 6.2 三路比较与 synth-three-way

`[array.syn]` 中的 `operator<=>` 返回 `synth-three-way-result<T>`，规则在 `[expos.only.func]`：`T` 支持 `<=>` 时直接使用它的结果；否则用 `<` 构造弱序，`a < b` 为 less，`b < a` 为 greater，两者都不成立为 equivalent。

返回类型因此由元素类型决定：

- `std::array<int, 3>` 的比较结果是 `std::strong_ordering`。
- `std::array<double, 3>` 的比较结果是 `std::partial_ordering`，出现 NaN 时结果为 unordered。
- 只提供 `<` 的元素类型得到 `std::weak_ordering`，两个不同对象可以比较为 equivalent。

```cpp
std::array<int, 2> x{1, 2}, y{1, 3};
bool lt = x < y;                    // true，字典序
auto c = x <=> y;                   // std::strong_ordering::less
```

### 6.3 实现路径

三家实现都按字典序比较，先找第一个不相等的元素，复杂度线性于 N，差异在于是否走块比较：

- libstdc++ 的 `operator==` 通过 `__equal_aux1`，对整数、指针与 `std::byte` 一类元素退化为 `memcmp`；`<=>` 只在 `__is_memcmp_ordered` 为真且不在常量求值时使用 `__builtin_memcmp`，其余情况逐元素调用 `__synth3way` [impl]。
- MSVC STL 的 `operator==` 调用 `std::equal`；`<=>` 调用 `std::lexicographical_compare_three_way`，比较器是 `_Synth_three_way` [impl]。
- libc++ 的 `operator==` 调用 `std::equal`；`<=>` 调用 `std::lexicographical_compare_three_way`，比较器是 `std::__synth_three_way` [impl]。

块比较是优化，不改变结果。对元素类型带有自定义 `<=>` 的数组，三者都逐元素调用该运算符。

### 6.4 比较的边界

- 两个 `std::array` 只有元素类型与 N 都相同时才能比较。不同 N 之间没有重载，需要先统一长度，或比较公共前缀。
- 元素类型必须支持相应的比较。`std::array<std::unique_ptr<T>, N>` 可以比较相等，但 `<` 比较的是地址，语义通常不是调用方想要的。
- 浮点元素用 `<=>` 得到偏序，`==` 与 `<=>` 对 NaN 的结论不同：`==` 为 false，`<=>` 为 unordered。
- 字符数组与字符串字面量不能直接比较。`std::array<char, 4>` 与 `"abc"` 之间没有重载，需要转成 `std::string_view`，或逐元素比较到结尾空字符为止。
- 比较要求元素类型完整且可比较。只有前置声明的类型不能参与比较。

## 7. tuple 接口与结构化绑定

### 7.1 tuple_size 与 tuple_element

`<array>` 为 `std::array` 提供 `tuple_size` 与 `tuple_element` 的偏特化，覆盖 cv 限定版本（`[array.tuple]`）：

```cpp
static_assert(std::tuple_size_v<std::array<int, 4>> == 4);
static_assert(std::is_same_v<std::tuple_element_t<0, std::array<int, 4>>, int>);
```

`tuple_size` 的值是 N，`tuple_element<I>` 的类型是 T。`I` 不小于 N 时 `tuple_element` 不完整，使用它是错误；诊断出现在实例化处，不在 `get` 调用处。

### 7.2 get 与结构化绑定

`std::get<I>(a)` 返回第 I 个元素的引用，四个重载覆盖左值、右值、const 左值与 const 右值，`I` 越界在编译期报错。结构化绑定依赖 `tuple_size` 与 `get`：

```cpp
std::array<int, 3> a{1, 2, 3};
auto [x, y, z] = a;      // 复制三个元素
auto& [r, s, t] = a;     // 绑定引用
r = 10;                  // 修改 a[0]
```

`auto [x, y, z]` 中的名字是副本，修改它们不影响数组；`auto&` 绑定的才是元素本身。名字个数必须等于 N，`std::array<int, 3>` 不能绑定两个名字，`std::array<int, 0>` 无法绑定（零个名字不是合法语法）。

`std::apply` 也能用于 `std::array`，因为它满足 tuple-like 的要求：

```cpp
int sum = std::apply([](int p, int q, int r) { return p + q + r; }, a);
```

### 7.3 适用边界

结构化绑定适合在已知 N 的场合展开元素，例如把定长记录拆成字段，或在小规模向量运算中命名分量。运行期下标仍然要用 `a[i]`，结构化绑定不能按下标取值。

绑定的名字可以是引用，也可以是值；`auto&&` 绑定到元素，保留值类别，转发场景下有用。取绑定名字的地址得到元素地址，与 `&a[i]` 相同。模板代码中展开全部元素通常用 `std::index_sequence` 配合 `get<I>`，结构化绑定只适合 N 已知且固定的位置。

## 8. constexpr 支持

### 8.1 版本演进

`std::array` 的常量求值能力是逐步扩大的：

| 版本 | 能力 |
| --- | --- |
| C++11 | `size()`、`max_size()`、`empty()` 是 `constexpr`；聚合初始化可用于 `constexpr` 变量 |
| C++14 | 常量重载的 `operator[]`、`at`、`front`、`back` 可常量求值（LWG 2443） |
| C++17 | 非常量重载与 `data()`、`begin()`、`end()` 成为 `constexpr`（P0031R0） |
| C++20 | `fill()`、`swap()`、`operator==`、`operator<=>` 成为 `constexpr`（P1032R1、P1023R0）；迭代器满足 constexpr 迭代器要求（P0858R0） |

特性宏对应两组值：`__cpp_lib_array_constexpr` 在 C++17 为 201603L，在 C++20 为 201811L。检查宏比检查语言版本可靠，因为实现可能提前提供部分能力。

### 8.2 实现方式

三家实现都用宏按语言版本切换 `constexpr`：libstdc++ 用 `_GLIBCXX17_CONSTEXPR` 与 `_GLIBCXX20_CONSTEXPR`，MSVC 用 `_CONSTEXPR17` 与 `_CONSTEXPR20`，libc++ 用 `_LIBCPP_CONSTEXPR_SINCE_CXX17` 与 `_LIBCPP_CONSTEXPR_SINCE_CXX20`。

`at` 的常量求值版本要把检查写成条件表达式。libstdc++ 的 const 重载把下标判断放进条件表达式的一支：合法时返回元素，越界时求值一个抛出 `std::out_of_range` 的调用。这种写法与 C++11 对 constexpr 函数体的限制一致，函数体只能是一条 return 语句；C++14 放宽限制后，实现仍保留这一形式。

### 8.3 编译期表与模板实参

`std::array` 最常见的常量求值用途是编译期表：

```cpp
constexpr std::array<int, 5> squares{0, 1, 4, 9, 16};
static_assert(squares[3] == 9);

template<std::array<int, 3> A>
struct Sum {
  static constexpr int value = A[0] + A[1] + A[2];
};
```

元素类型是 structural type 时，`std::array` 本身也是 structural type，可以作为非类型模板参数（`[array.overview]/4`）。两个数组在每对对应元素都 template-argument-equivalent 时是同一个模板实参，这条规则让编译期表可以参与模板选择与缓存。

### 8.4 限制

- 越界访问、读取未初始化元素、调用未标记 `constexpr` 的成员，都会让常量表达式失败。`at` 越界在常量求值中表现为常量表达式不合法，不会抛出异常。
- 元素是指针时，常量求值要求指针指向具有静态存储期的对象，或为空指针。指向常量求值期间临时对象的指针不能带到运行期。
- `std::array` 的 `fill` 与 `swap` 到 C++20 才能常量求值，C++17 的常量求值代码不能使用它们。
- 常量求值中的 `std::array` 没有运行期地址稳定性要求；`constexpr` 变量本身有存储期，取地址在运行期合法。

## 9. 参数、返回值与成员

### 9.1 作为函数参数

按值传递 `std::array` 复制 N 个元素，成本由元素类型决定。`std::array<char, 1024>` 的复制要处理 1024 个字节，`std::array<std::string, 8>` 的复制是 8 次字符串复制。需要避免复制时用 `const` 引用，函数模板可以同时推导元素类型与长度：

```cpp
template<class T, std::size_t N>
std::size_t count_nonzero(const std::array<T, N>& a);
```

需要接受任意连续范围时用 `std::span<const T>`，代价是丢失静态长度；需要静态长度参与重载或编译期检查时保留 `std::array` 参数。与 C 接口交界处传 `a.data()` 与 `a.size()`，不要传数组本身。

### 9.2 作为返回值

`std::array` 可以按值返回。C++17 起用纯右值初始化对象时保证复制消除，因此直接返回字面量或临时对象不产生额外复制；返回局部变量依赖 NRVO，标准不保证。元素类型可平凡复制时，返回等价于复制 N 个元素的内存；不可平凡复制时逐个复制或移动，移动是否发生由返回表达式的值类别与复制消除规则决定。

没有分配意味着返回值不会抛 `bad_alloc`，也没有迭代器与容量需要维护。大规模结果仍应考虑 `vector` 或输出参数，原因在栈空间与复制成本，而不在 `std::array` 的语义。

### 9.3 作为类成员

`std::array` 作为类成员不引入间接层，外层对象的大小增加 N 乘 `sizeof(T)`，对齐取两者的较大值。聚合初始化可以逐层写入，类内默认成员初始化器可以写 `std::array<int, 3> v{};`。

非静态数据成员不能用类模板实参推导，成员声明必须写全类型，`std::array v{1, 2, 3};` 作为成员不合法。这一点与局部变量不同，也是类内使用 `std::array` 时最常见的语法错误。

### 9.4 与 C 数组的退化差异

| 维度 | 内建数组 | `std::array` |
| --- | --- | --- |
| 作为函数参数 | 退化为指向首元素的指针，长度丢失 | 不退化，按值或引用传递，长度保留 |
| 赋值与返回 | 不能赋值，不能按值返回 | 可赋值，可按值返回 |
| 长度来源 | `sizeof(a) / sizeof(a[0])` 或显式常量 | `size()`、N、`tuple_size` |
| 比较 | 比较指针，不比较元素 | 逐元素比较 |
| 长度推导 | `int a[] = {1, 2, 3}` 可数出长度 | 必须写 N，或用 CTAD、`to_array` |

前三行是类型层面的差别，第四行是语义差别，第五行是初始化差别。内建数组的 `==` 比较指针，是 C 代码中常见的错误；`std::array` 的 `==` 比较元素。内建数组作为类成员时不能赋值，含数组的类因此难以复制；`std::array` 没有这个限制。

反过来的代价是长度必须显式给出。C++17 的 CTAD 只覆盖「所有元素同型」的初始化器列表，C++20 的 `to_array` 只覆盖已有的内建数组；两者都不能从任意表达式序列推导长度。

## 10. ABI 与跨模块传递

### 10.1 布局层面的稳定性

`std::array` 没有分配、没有虚函数、没有用户声明的特殊成员。元素类型布局稳定时，`std::array` 的布局也稳定；元素类型平凡可复制时，`std::array` 平凡可复制，可以按字节复制，也可以在大小相同的平凡可复制类型之间使用 `std::bit_cast`。

跨模块按值传递 `std::array<int, 4>` 只依赖调用约定与布局，不依赖标准库内部状态。这是它比 `std::string`、`std::vector` 更适合跨边界接口的原因：后两者的布局与分配器、调试档、ABI 宏相关，跨边界传递需要额外约定。

标准没有把布局写成规范要求，只保证连续性与恒等式。跨模块一致的前提是双方使用同一编译器、同一标准库版本与同一 ABI 选项。

### 10.2 迭代器不是稳定接口

`iterator` 由实现定义（第 3.4 节），把它写进导出函数的签名会把这些差异带进接口：

- MSVC STL 的迭代器是类类型，`_ITERATOR_DEBUG_LEVEL` 影响其大小与检查逻辑，调试档与发布档的目标文件不能混用。
- libc++ 的迭代器类型由 ABI 宏决定。两个翻译单元定义不同的 ABI 宏属于 ODR 违反，症状通常是链接成功而运行时行为异常。
- libstdc++ 用 `T*`，类型稳定，但同样的接口在另外两家实现上不成立。

可行的做法是跨模块接口只出现 `T*` 加长度、`std::span`，或 `std::array` 的引用。迭代器留在模块内部使用。

### 10.3 调试与加固档位

- MSVC STL：`_ITERATOR_DEBUG_LEVEL` 非 0 时 `operator[]` 检查下标，迭代器保存下标并校验；`_MSVC_STL_HARDENING_ARRAY` 单独控制 `std::array` 的加固检查。
- libstdc++：`_GLIBCXX_ASSERTIONS` 打开 `__glibcxx_requires_subscript` 等前置条件检查，`_GLIBCXX_DEBUG` 不改变 `std::array` 的布局与迭代器类型。
- libc++：`_LIBCPP_HARDENING_MODE` 控制 `_LIBCPP_ASSERT_VALID_ELEMENT_ACCESS`，档位包括 none、fast、extensive 与 debug。

三家的 `std::array` 本身都没有调试成员，对象布局不随档位变化；变化落在迭代器类型与 inline 函数体上。混合档位时，传递对象本身安全，传递迭代器不安全。

### 10.4 与 C 结构体的布局互操作

标准只保证元素连续与 `&a[n] == &a[0] + n`，没有声明 `std::array` 内含一个 `T[N]` 对象。实际影响有两面：

- 三家实现都用 `T[N]` 作为唯一成员，把 `std::array<T, N>` 放进与 `T[N]` 相同的结构体布局在实践上可行 [推断]。
- 需要严格保证时，C 接口一侧用 `T[N]` 或指针加长度，C++ 一侧在边界上转换。不要依赖 `reinterpret_cast<T(*)[N]>(a.data())`：标准没有承诺存在对应的数组对象，严格说，这类指针不指向标准意义上的数组对象。

## 11. 与 vector 的选型

### 11.1 能力对照

| 维度 | `std::array` | `std::vector` | `std::inplace_vector` |
| --- | --- | --- | --- |
| 容量 | 编译期固定 N | 运行期增长 | 编译期上限 N，长度可变 |
| 分配 | 无 | 有 | 无 |
| 元素地址 | 位于对象内，稳定 | 重分配后失效 | 位于对象内，稳定 |
| 增长接口 | 无 | 有 | 有，满时抛 `std::bad_alloc` |
| 适合场景 | 定长、无分配 | 长度未知 | 长度不定但不超过 N |

`std::inplace_vector` 是 C++26 的组件（P0843R14），已进入工作草案。它与 `std::array` 的区别在长度：容量上限在编译期确定，实际长度在运行期变化；相同点是元素内嵌在对象里，不做动态分配。

### 11.2 选择规则

- 长度在编译期确定、不需要增长时用 `std::array`。布局与内建数组一致，适合与 C 接口、共享内存、固定格式的序列化对接。
- 长度在运行期确定时用 `vector`；需要避免分配且长度有上限时用 `inplace_vector`。
- 不把 `std::array` 当作容量固定的 `vector`。它没有 `push_back`、`resize`、`erase`，也没有运行期长度，把这些需求交给 `inplace_vector` 或 `vector`。
- 大对象优先放在堆上。`std::array` 的大小计入外层对象，外层对象放在栈上时，大数组随之占用栈空间。
- 定长但元素数量很大时，`vector` 的一次分配可能比在对象内放置大数组更合适，具体取决于对象的生命周期与复制次数。

## 12. 演进与工程实践

### 12.1 版本变化

| 版本 | 与 `std::array` 相关的变化 |
| --- | --- |
| C++11 | 进入标准；聚合初始化、`at`、`data`、`fill`、`swap`、tuple 接口 |
| C++14 | 常量重载的访问函数成为 `constexpr`（LWG 2443） |
| C++17 | 连续容器要求；推导指引（P0433R2）；`data()`、`begin()` 等成为 `constexpr`（P0031R0） |
| C++20 | `to_array`（P0325R4）；`operator<=>`（P1614R2）；`fill`、`swap` 与比较的 `constexpr`（P1032R1、P1023R0）；structural type |
| C++23 | 接口无变化 |
| C++26 | 加固前置条件（P3471R4）与契约措辞（P2900R14），布局与接口不变 |

C++26 的两项仍以工作草案为准。加固把越界下标从「未定义行为」变成「可诊断的失败」，契约措辞替换了部分成员的未定义行为描述，两者都不改变 `std::array` 的对象模型。

### 12.2 加固与调试

C++26 的加固（P3471R4）在 `[sequence.reqmts]` 中为 `a[n]` 写了 Hardened preconditions。启用加固时，越界下标变成库内可诊断的失败；关闭加固时没有运行时开销。`at` 不受加固影响，始终检查并抛 `std::out_of_range`。

三家实现的开关与检查点：

- MSVC STL 在 `operator[]` 中按 `_MSVC_STL_HARDENING_ARRAY` 或 `_ITERATOR_DEBUG_LEVEL` 决定是否调用 `_STL_VERIFY`。
- libstdc++ 在 `operator[]` 中调用 `__glibcxx_requires_subscript`，该宏由 `_GLIBCXX_ASSERTIONS` 控制。
- libc++ 在 `operator[]` 中调用 `_LIBCPP_ASSERT_VALID_ELEMENT_ACCESS`，由 `_LIBCPP_HARDENING_MODE` 控制。

加固只增加检查，不改变对象布局与函数签名。加固是编译期选择，同一程序内各翻译单元应保持一致：inline 函数体随档位变化，混用不同档位属于 ODR 违反，症状通常是运行时行为不一致，链接仍可能成功。

### 12.3 陷阱清单

| 写法 | 问题 | 修正 |
| --- | --- | --- |
| `std::array<int, 3> a;` 后读取元素 | 默认初始化，元素值不确定 | 用 `a{}` 或逐个初始化 |
| `a == "abc"` | 没有跨类型比较重载 | 转 `std::string_view`，或逐元素比较 |
| 保存 `begin()` 后调用 `swap` | 迭代器仍与数组关联，值已交换 | 交换后重新获取，或保存下标 |
| 跨模块传 `array::iterator` | 迭代器类型由实现与调试档决定 | 传 `data()` 与长度，或传容器引用 |
| 依赖 `sizeof(array<T, 0>)` 为 0 | 大小至少为 1，具体值由实现定义 | 用 `empty()` 判断，不把零长数组当零大小成员 |
| 在 `noexcept` 函数中调用 `at` | 越界抛 `out_of_range` 会终止程序 | 用 `operator[]` 并自行保证下标，或在外层捕获 |

---

## 结论

`std::array` 的行为由一条布局事实推出：对象里只有 N 个连续元素，长度是类型的一部分。由此得到常数时间的访问、稳定的元素地址、零分配、可平凡复制的对象表示，也得到不能增长、不能运行期定长、不能把零长数组当作零大小成员的限制。

可执行的规则有五条：

1. 长度在编译期已知时用 `std::array`；需要增长或运行期长度时用 `vector`；上限固定而长度可变时用 `inplace_vector`。
2. 一律用花括号初始化。`std::array<int, 3> a;` 的元素值不确定，`a{}` 才得到全零。
3. 传参用 `const std::array<T, N>&` 保留长度信息；跨 C 接口传 `data()` 与 `size()`；跨模块不传迭代器。
4. 比较依赖 `<=>` 时确认元素类型的比较类别，浮点数组得到偏序；不同 N 的数组先统一长度再比较。
5. 在 `noexcept` 路径上用 `operator[]` 并自行保证下标，`at` 留给需要诊断的边界。

把 `std::array` 看作带类型与接口的内建数组，比把它看作容量固定的 `vector` 更接近事实。前者解释了它的布局、初始化与传参规则，后者只会引出对增长接口的期待。
