## 0. 结论摘要

重载决议是在一组同名函数中选出唯一调用的过程。它使用名字查找与模板推导产生的候选集与实参列表，自身不负责这两步。

- 过程分三步：建立候选集，筛出可行函数，选出最优可行函数（[over.match.general]/2）。
- 可行要求参数个数匹配、关联约束满足、每个实参都存在隐式转换序列。
- 隐式转换序列分标准转换、用户定义转换、省略号转换三种。标准序列的等级由最差分量决定：Exact Match、Promotion、Conversion。一次隐式转换最多包含一个用户定义转换。
- 排序是逐参数的偏序：一个函数在所有参数上都不劣于另一个函数，并且至少在一个参数上更好，才可能胜出。不可比即二义。
- 平局按固定次序裁决：标准序列的子序列与等级、引用绑定、指针与继承关系、非模板优先、模板偏序、约束偏序、改写候选。
- 删除函数与访问权限不参与排序。删除函数可以成为最优候选，随后调用 ill-formed；访问检查在决议之后。
- 返回类型不参与重载决议。函数模板先做推导，推导失败只淘汰该候选。
- C++20 的改写候选与约束偏序、C++23 的显式对象参数，是近几个版本中改变候选集与对象参数匹配的主要变化。

## 1. 范围与口径

重载决议的规则集中在 [over.match]，名字查找、模板推导、约束满足、访问控制分散在相邻条款。本文按决议发生的顺序组织：候选集如何形成，可行函数如何筛出，隐式转换序列如何比较，平局如何裁决，最后回到初始化、运算符与取地址这些具体上下文。

### 1.1 证据分级与版本基准

标准草案是主要依据，提案与实现行为只在解释来源或边界时引用。本文用下列标记区分证据：

标准侧以 eel.is 的 2026-11 草案快照为准，C++11、C++17、C++20、C++23 分别用 N3337、N4659、N4861、N4950 对照。草案不是正式标准，正式文本是 ISO/IEC 14882；段号对应快照，标准换版后可能位移。

同一套决议规则从 C++11 起经历过几次实质修改：引用限定、列表初始化、删除函数、显式转换函数在 C++11 加入；约束与改写候选在 C++20 加入；显式对象参数在 C++23 加入。正文在涉及版本差异处单独标注。

### 1.2 不做什么

- 不展开名字查找、ADL 与模块的完整规则，只保留它们对候选集的影响。
- 不展开模板参数推导的完整算法，只讨论推导失败、显式实参与偏序在决议中的位置。
- 不展开对象布局、调用约定与 ABI，相关内容见[《C++ 对象模型》](/post/2026/10/14/cpp-object-model/)。
- 不展开虚函数分派；重载决议在编译期选择签名，虚函数在运行期选择最终覆盖者，这是两层机制。
- 不讨论编译器扩展与反射提案，也不给出性能结论。

## 2. 决议模型与上下文

### 2.1 三个集合

重载决议的输入是候选函数集合与实参列表，输出是唯一的最优可行函数，或者失败。标准把这个过程拆成三步（[over.match.general]/2）：先筛出可行函数，再按隐式转换序列选出最优者。

```text
candidates = 上下文规定的候选集
viable     = { f ∈ candidates | 参数个数匹配
                              ∧ 关联约束满足
                              ∧ 对每个实参 i，存在 ICS(arg_i, P_i) }
best       = { f ∈ viable | 对每个 g ∈ viable，f 不劣于 g，
                            且存在 j 使 f 在 j 上更好 }
```

`best` 要么恰有一个元素，要么为空。为空表示不存在一个函数优于所有其他可行函数，此时调用 ill-formed（[over.match.best.general]/3）。

这里的「更好」是逐参数定义的偏序，不把各参数转换折算成总分。某个函数可以在第一个参数上更好、在第二个参数上更差，此时两个函数不可比（[over.match.best.general]/2）。

标准对这组规则的定义是描述性的。实现不必真的构造候选集、逐个计算转换序列，只要结果与规则一致（[over.match.funcs.general]/1）。

### 2.2 七个上下文

候选集由调用出现的语法上下文决定。当前草案列出七种（[over.match.general]/2）：

| 上下文 | 候选集 | 实参列表 | 条款 |
| --- | --- | --- | --- |
| 函数调用 `f(a)` | 查找结果，成员或非成员 | 实参；成员调用前置隐含对象 | [over.call.func] |
| 类对象调用 `obj(a)` | `operator()` 与代理调用函数 | 对象与实参 | [over.call.object] |
| 运算符 `a @ b` | 成员、非成员、内建、改写 | 操作数 | [over.match.oper] |
| 构造（默认或直接初始化） | 构造函数 | 初始化器 | [over.match.ctor] |
| 拷贝初始化中的用户定义转换 | 非 explicit 构造函数与转换函数 | 初始化表达式 | [over.match.copy] |
| 非类类型初始化 | 转换函数 | 初始化表达式 | [over.match.conv] |
| 直接引用绑定 | 转换函数 | 初始化表达式 | [over.match.ref] |

列表初始化与类模板实参推导不在这七项里，它们复用同一套选择机制：[over.match.list] 规定列表初始化的构造函数选择，[over.match.class.deduct] 规定 CTAD 的候选与平局。取重载集地址由 [over.over] 单独规定，它按目标类型选择，不按实参排序。

### 2.3 名字查找先于决议

候选集首先由名字查找决定。限定调用 `N::f(x)` 只在 `N` 中查找；非限定调用 `f(x)` 先做普通查找，再对每个实参的关联命名空间与关联类做 ADL（[basic.lookup.argdep]）。成员调用 `obj.f(x)` 在 `obj` 的类作用域查找，不使用 ADL。

派生类中的同名成员会隐藏基类成员，除非用 `using` 声明重新引入。名字隐藏在决议之前发生，重载决议不会跨越作用域去合并被隐藏的名字。

```cpp
struct B { void f(int); };
struct D : B { void f(double); };

void g(D& d) {
    d.f(1); // 调用 D::f(double)，B::f(int) 不在候选集
}
```

ADL 只扩大非限定调用的候选集。下面的调用能通过 ADL 找到 `lib::f`，限定调用 `lib::f(s)` 则不做 ADL：

```cpp
namespace lib {
struct S {};
void f(S);
}

void g() {
    lib::S s;
    f(s); // ADL 把 lib::f 加入候选集
}
```

## 3. 候选函数

### 3.1 隐式对象参数

非静态成员函数在决议中多一个参数，称为隐式对象参数（implicit object parameter）。它的类型由成员函数的 cv 限定与 ref 限定决定（[over.match.funcs.general]/4）：

| 声明 | 隐式对象参数类型 | 说明 |
| --- | --- | --- |
| `void f();` | `X&` | 无 ref 限定 |
| `void f() const;` | `const X&` | 无 ref 限定 |
| `void f() &;` | `X&` | 只绑定左值 |
| `void f() const &;` | `const X&` | 只绑定左值 |
| `void f() &&;` | `X&&` | 只绑定右值 |
| `void f() const &&;` | `const X&&` | 只绑定右值 |
| `static void f();` | 无实际类型 | 匹配任意对象，不形成转换序列 |
| `void f(this X&);` | 无隐式参数 | 对象实参匹配显式参数 |

隐式对象参数保留自己的身份：不能对其实施用户定义转换，对象实参只用标准转换匹配它（[over.match.funcs.general]/5）。对于没有 ref 限定的成员函数，右值对象可以绑定到非 const 的左值引用对象参数，只要其余条件满足；这种右值性不影响转换序列的排序（同条）。

```cpp
struct S {
    void f() &;
    void f() &&;
    void g();
};

S{}.f(); // 调用 f() &&
S{}.g(); // OK：g 无 ref 限定，右值绑定到 S&
```

`f` 的两个重载的对象参数分别是 `S&` 与 `S&&`。对右值对象，`S&&` 的绑定更好（[over.ics.rank]/3.2.3）。`g` 没有 ref 限定，右值按上面的特殊规则绑定到 `S&`。

`static` 成员函数的对象匹配不产生转换序列，它在比较中既不更好也不更差（[over.best.ics.general]/8）。这一条会让静态成员与另一个可行候选在对象参数上打平，进而由其他参数或平局规则决定。

转换函数被视为对象实参所属类的成员；`using` 声明引入的成员被视为引入它的派生类的成员。这两种处理都会改变隐式对象参数的类型（[over.match.funcs.general]/4）。

### 3.2 函数模板候选

候选中的函数模板先做模板实参推导，生成函数模板特化（[temp.over]、[temp.deduct]）。推导失败只淘汰该候选，不使程序错误；这就是 SFINAE 的基本位置。失败发生在替换的立即上下文之外时不属于 SFINAE，会直接产生错误。

显式模板实参、默认模板实参、参数包都参与候选生成。推导成功后，函数模板特化与普通函数在后续步骤中等价，只在平局规则中区分（第 6.4 节）。

```cpp
template<class T> requires std::integral<T>
void h(T);

template<class T>
void h(T*);

void g() {
    h(1);       // 第一个候选；第二个推导失败
    h((int*)0); // 第二个候选；第一个约束不满足
}
```

候选生成发生在约束检查之前。第二个调用里，第二个模板的推导成功，第一个模板的约束在可行集筛选时失败（[over.match.viable]/3）。

### 3.3 构造函数与转换函数

构造函数没有隐式对象参数。直接初始化与默认初始化考虑全部构造函数，拷贝初始化只考虑非 explicit 构造函数（[over.match.ctor]、[over.match.copy]）。

```cpp
struct A {
    explicit A(int);
};

A a = 1; // 错误：拷贝初始化不考虑 explicit 构造函数
A b(1);  // OK：直接初始化
```

转换函数的候选集取决于上下文与目标类型。拷贝初始化只考虑非 explicit 转换函数；直接初始化在目标类型只差限定转换时也考虑 explicit 转换函数（[over.match.conv]、[over.match.ref]）。

```cpp
struct B {
    explicit operator int() const;
};

B b;
int i = b;      // 错误：拷贝初始化只考虑非 explicit 转换函数
int j = int(b); // OK：直接初始化
```

在拷贝初始化一个类类型对象时，候选同时包括目标类型的非 explicit 构造函数与源类型的转换函数，但一次隐式转换只允许一个用户定义转换（[over.best.ics.general]/4）。这条限制让 `T t = s;` 不会尝试 `T(S(S))` 这类两级转换。

### 3.4 代理调用函数

对类对象调用 `obj(args)`，候选包括 `operator()`，还可能包括代理调用函数（surrogate call function）。每个非 explicit 且返回函数指针、函数指针引用或函数引用的转换函数，会生成一个代理候选：第一个参数是转换结果类型，后面是函数的参数（[over.call.object]/2）。

```cpp
using Fn = int(*)(int);
int f(int);

struct C {
    operator Fn() const { return f; }
};

C c;
int x = c(1); // 通过代理调用函数调用 f
```

对象实参到代理候选第一个参数的转换是用户定义转换；如果没有 `operator()`，代理候选是唯一来源。若 `C` 同时定义了 `operator()`，对象参数上的恒等匹配通常会让 `operator()` 胜出。

### 3.5 列表初始化的两阶段

列表初始化一个非聚合类时，构造函数分两阶段选择（[over.match.list]/1）：

1. 如果初始化列表非空，或类型没有默认构造函数，先只考虑 `initializer_list` 构造函数，把整个列表作为一个实参。
2. 否则，或第一阶段没有可行函数，再考虑全部构造函数，把列表元素作为实参。

拷贝列表初始化中如果最终选中 explicit 构造函数，初始化 ill-formed。这与普通拷贝初始化不同：普通拷贝初始化根本不把 explicit 构造函数放进候选集，而列表初始化会先选，再检查。

```cpp
std::vector<int> a{10, 20}; // 两个元素
std::vector<int> b(10, 20); // 10 个 20
```

`initializer_list` 构造函数优先级高于元素转换的优劣。下面的调用选择 `initializer_list<long>`，即使 `42` 到 `int` 是精确匹配，到 `long` 只是转换：

```cpp
void f1(int);
void f1(std::initializer_list<long>);

f1({42}); // 调用 initializer_list<long>
```

## 4. 可行函数

### 4.1 参数个数与默认实参

候选函数必须与实参个数相容（[over.match.viable]/2）：

- 形参个数等于实参个数时，直接可行。
- 形参个数少于实参个数时，只有带省略号的函数可行；多出的实参按匹配省略号处理。
- 形参个数多于实参个数时，只有尾部形参全部有默认实参时才可行；参数列表在右侧截断到实参个数。

默认实参不进入函数类型，也不参与参数类型匹配。它们只让候选在个数上可行，实际使用的默认实参由声明提供。如果最优函数依赖默认实参，而这些默认实参来自不同作用域，调用 ill-formed（[over.match.viable]/2.3）。这条规则针对同一函数在多个作用域中重复声明、各自给出不同默认实参的情形。

参数包可以展开为零个或多个参数，因此可变参数模板在实参较少时仍可能可行。省略号与参数包的区别在于：省略号接受任意类型且不检查转换，参数包展开后仍按普通形参匹配。

### 4.2 约束

关联约束不满足的候选不可行（[over.match.viable]/3）。这条规则同时适用于函数模板与受约束的普通函数。约束检查排在参数个数之后、隐式转换序列之前：先确认形状与适用条件，再计算转换。

约束失败是候选被淘汰，不产生硬错误。原子约束替换是否属于 SFINAE，取决于失败是否发生在立即上下文。概念（concept）定义体中的错误通常直接报错，不属于替换失败；`requires` 子句中的替换失败属于 SFINAE。

### 4.3 隐式转换序列存在

对每个实参，必须存在一个隐式转换序列。引用参数还要能完成绑定，因此下面两种情况直接使候选不可行（[over.ics.ref]/3）：

- 非 const 左值引用不能绑定右值。
- 右值引用不能绑定左值。

列表初始化中的窄化转换不能形成序列，候选因此不可行；这类失败在诊断中通常显示为「无法从初始化列表转换」。

### 4.4 删除、访问与可用候选

删除函数仍参与重载决议。`= delete` 的作用是让被选中的函数在调用处报错，同时让其他重载继续参与候选。若把删除函数提前排除，调用可能静默落到一个更差的可行函数上。

```cpp
void f(int);
void f(double) = delete;

f(1.0); // 选择 deleted f(double)，随后 ill-formed
```

有两条例外会把候选排除在候选集之外：定义为删除的默认移动构造函数或移动赋值运算符（[over.match.funcs.general]/9），以及在某些单实参情形下与派生类拷贝或移动构造冲突的继承构造函数（同条）。前者避免删除的移动成员干扰拷贝路径，后者避免继承构造函数抢占派生类的拷贝或移动构造。

访问控制不在决议内。标准规定，决议成功但最优函数不可访问时，程序 ill-formed（[over.match.general]/3）。因此私有重载可以压过公有重载，然后在访问检查处报错：

```cpp
class X {
    void f(int);
public:
    void f(double);
};

void g(X& x) {
    x.f(1); // 选择 private f(int)，随后报访问错误
}
```

当前草案把「决议成功，且选中者未删除、可访问，或选中者不是函数（内建候选）」称为可用候选（usable candidate，[over.match.general]/4）。这个术语把决议结果与最终能否调用分开。

## 5. 隐式转换序列

### 5.1 三种形式

隐式转换序列描述一个实参如何转换为一个形参。它有三种形式（[over.best.ics.general]/3），比较时先看形式（[over.ics.rank]/2）：

| 形式 | 构成 | 典型来源 | 相对次序 |
| --- | --- | --- | --- |
| 标准转换序列 | 0 至 3 个标准转换 | 算术类型、指针、引用绑定 | 最好 |
| 用户定义转换序列 | 标准转换 + 用户定义转换 + 标准转换 | 转换函数、转换构造函数 | 次之 |
| 省略号转换序列 | 匹配省略号 | `...` 形参 | 最差 |

隐式转换序列只考虑类型、cv 限定与值类别。生命周期、存储期、对齐、可访问性、是否为位域、函数是否删除，都不影响序列的形成（[over.best.ics.general]/2）。这些属性在决议之后检查，因此「有转换序列」不等于「调用合法」。

### 5.2 标准转换序列

标准转换分为四类（[over.ics.scs]/1）：

| 类别 | 包含 | 等级 |
| --- | --- | --- |
| 左值变换 | 左值到右值、数组到指针、函数到指针 | Exact Match |
| 提升 | 整型提升、浮点提升 | Promotion |
| 转换 | 整型、浮点、浮点整型、指针、成员指针、布尔 | Conversion |
| 限定调整 | 限定转换、函数指针转换 | Exact Match |

标准序列要么是恒等转换，要么由一至三个转换按固定顺序组成：左值变换、提升或转换、限定调整（[over.ics.scs]/2）。序列的等级取各分量中最差的一个，引用绑定的等级也计入（[over.ics.scs]/3）。

派生类到基类的转换不是标准转换，它只作为隐式转换序列的描述存在，等级为 Conversion（[over.best.ics.general]/7）。

```cpp
void f(int);
void f(long);
f('a'); // 调用 f(int)：整型提升优于整型转换

void g(int*);
void g(const int*);
int* p = nullptr;
g(p); // 调用 g(int*)：限定更少
```

### 5.3 引用绑定

参数是引用时，隐式转换序列包含绑定操作（[over.ics.ref]/1）。直接绑定的情况有四类：

- 实参是形参类型的派生类：派生类到基类转换，等级 Conversion。
- 实参类型与形参类型相同（忽略顶层 cv）：恒等转换。
- 形参是函数类型：函数指针转换。
- 其余情况：限定转换。

不能直接绑定时，按被引用类型创建临时对象再绑定。此时非 const 左值引用不能绑定右值，右值引用不能绑定左值（[over.ics.ref]/3）。const 左值引用可以绑定右值，临时对象保持有效到包含该调用的完整表达式结束。

```cpp
void h(int&);
void h(const int&);

h(1); // 调用 const int&：int& 不能绑定右值
```

位域是另一个边界。隐式转换序列可以把位域当作对应整型的左值形成，但真正绑定非 const 左值引用时 ill-formed（[over.ics.ref]/4）。这类限制在决议之后报错，不改变可行性。

### 5.4 用户定义转换序列

用户定义转换序列由三段组成：初始标准转换、用户定义转换、第二标准转换（[over.ics.user]/1）。构造函数版本把实参转换到第一个形参类型；转换函数版本把实参转换到对象参数类型。第二标准转换把转换结果调整到目标类型，引用绑定也包含在这一段。

除列表初始化的元素外，隐式转换序列最多包含一个用户定义转换（[over.best.ics.general]/4）。这条限制保证序列有限，也解释了为什么两级用户定义转换不会被考虑。

同一个转换函数或构造函数被选中时，第二标准转换更好者胜（[over.ics.rank]/3.3）。转换函数模板要求第二标准转换是 Exact Match（[over.ics.user]/3）。类到自身是 Exact Match，类到基类是 Conversion（[over.ics.user]/4）。

```cpp
struct A {
    operator int();
    operator double();
};

A a;
int i = a;   // operator int：第二段恒等
float x = a; // 二义：int 与 double 到 float 都要转换
```

### 5.5 列表初始化序列

初始化列表不是表达式，到形参的转换按专门规则形成（[over.ics.list]）。主要情形如下：

- 形参是 `std::initializer_list<X>`：序列取每个元素到 `X` 的转换中最差的一个；空列表是恒等转换。元素转换可以是用户定义转换，这是对「一次用户定义转换」限制的例外（[over.ics.list]/5）。
- 形参是数组：逐元素转换，取最差；已知边界优于未知边界，元素少者优于多者（[over.ics.rank]/3.1.2）。
- 形参是聚合类：按聚合初始化形成用户定义转换序列，第二段恒等；指定初始化器只对聚合有效。
- 形参是非聚合类：先按 [over.match.list] 选构造函数，再形成用户定义转换序列，第二段恒等；单元素且类型相同或派生时，等级分别是 Exact Match 与 Conversion。
- 形参不是类：单元素转换，或空列表的恒等转换；窄化转换不成立。

```cpp
void f(int);
void f(std::initializer_list<long>);
f({42}); // 调用 initializer_list<long>

void g(std::pair<const char*, const char*>);
void g(std::initializer_list<std::string>);
g({"foo", "bar"}); // 调用 initializer_list<std::string>
```

第二例中，每个 `const char*` 元素都通过用户定义转换变成 `std::string`。`initializer_list` 候选仍然胜出，因为 `initializer_list` 形参优先于其他形参（[over.ics.rank]/3.1.1）。

窄化会使序列无法形成：

```cpp
void h(int);
h({1.0}); // 错误：double 到 int 是窄化转换
```

### 5.6 歧义转换序列

如果同一个实参到同一个形参存在多个合法序列，标准把该形参对应的序列定义为歧义转换序列（ambiguous conversion sequence），并按用户定义序列参与排序，且与任何其他用户定义序列不可区分（[over.best.ics.general]/12）。这样函数不会因为一个形参的转换有歧义而直接不可行；若该函数最终被选中，调用在转换处 ill-formed。

```cpp
struct B;
struct A { A(B&); };
struct B { operator A(); };
struct C { C(B&); };

void f(A);
void f(C);

void g(B& b) {
    f(b); // 二义：b 到 A 有两条路径，b 到 C 一条路径
}
```

`b` 到 `A` 有构造函数与转换函数两条路径，形成歧义序列；`b` 到 `C` 是普通用户定义序列。两者在排序中不可区分，调用二义。

## 6. 排序与平局裁决

### 6.1 逐参数比较

最优可行函数的定义是：对所有实参 `i`，`F1` 的转换序列不劣于 `F2`；并且存在某个实参 `j`，`F1` 的序列更好（[over.match.best.general]/2）。这是偏序，不保证任意两个函数可比。

```cpp
void f(const int*, short);
void f(int*, int);

int i = 0;
short s = 0;
f(&i, s); // 二义
```

第一个参数上 `int*` 更好，第二个参数上 `short` 更好。两个函数互不逊色，调用二义。

### 6.2 标准序列的平局规则

两个标准序列等级相同时，按下列规则继续比较（[over.ics.rank]/3.2）：

- 子序列：`S1` 是 `S2` 的真子序列，比较时排除左值变换；恒等序列是任何非恒等序列的子序列。
- 引用绑定：两者都含引用绑定，且都不涉及没有 ref 限定的非静态成员函数的隐式对象参数时，绑定右值引用的序列优于绑定左值引用的序列。
- 函数引用：绑定到函数左值的左值引用优于绑定到同一函数左值的右值引用。
- 限定：两个序列只差限定转换、结果类型相似，且 `const T2` 与 `T1` 引用兼容时，限定更少者胜。
- 引用兼容：`S1` 绑定 `T1`、`S2` 绑定 `T2`，`T2` 与 `T1` 引用兼容且类型不同时，绑定更派生类型的序列更好。
- 同引用类型、不同源类型：比较源指针到目标指针的标准转换，更好者胜。

```cpp
void g(int&&);
void g(const int&);
g(1); // 调用 int&&：右值引用绑定右值

void k(int&);
void k(const int&);
int i = 0;
k(i); // 调用 int&：限定更少

void m(int);
void m(const int&);
m(1); // 二义：两条序列都是 Exact Match，没有规则可分
```

最后一例说明平局规则并不覆盖所有组合。按值传递与 const 引用绑定在等级上相同，标准没有规定谁更好。

### 6.3 用户定义序列的平局

两个用户定义序列只有在包含同一个转换函数或构造函数，或初始化同一个聚合类时，才比较第二标准转换（[over.ics.rank]/3.3）。不同的转换函数即使第二段优劣明显，也相互不可区分。

```cpp
struct A {
    operator short();
};

void f(int);
void f(float);

A a;
f(a); // 调用 f(int)：short 到 int 优于 short 到 float
```

### 6.4 函数之间的平局

转换序列无法分出胜负时，按候选函数的性质裁决（[over.match.best.general]/2）。下表中的条件按顺序检查，先满足者胜：

| 次序 | 条件 | 作用 |
| --- | --- | --- |
| 2.2 | 初始化由用户定义转换完成，第二段到目标类型更好 | 选择转换结果更接近目标的转换函数 |
| 2.3 | 函数类型引用的直接绑定，返回引用种类与待绑定引用相同 | 区分返回左值引用与右值引用的转换函数 |
| 2.4 | 一个不是函数模板特化，另一个是 | 非模板优先 |
| 2.5 | 两者都是模板特化，一个模板更特殊 | 模板偏序 |
| 2.6 | 两者都是非模板函数，一个更受约束 | 约束偏序 |
| 2.7 | 一个是派生类构造函数，另一个是基类构造函数，对应形参类型相同 | 继承构造函数不抢占派生类构造 |
| 2.8 | 一个是改写候选，另一个不是 | 原始运算符优先 |
| 2.9 | 两者都是改写候选，一个是反转参数的合成候选 | 非反转优先 |

2.6 的「更受约束」只对非模板函数成立，并且要求两者参数类型列表相同、属于同一个类（若为成员函数）（[temp.constr.order]/6）。2.7 针对继承构造函数：派生类自己的构造函数优先于从基类继承来的构造函数。

### 6.5 函数模板偏序

两个模板特化在转换序列上打平时，比较模板的偏序（[temp.func.order]）。做法是对每个模板参数合成唯一的类型、值或模板，替换到函数类型中，得到转换后的模板；再用这个函数类型对另一个模板做推导。

- 只在一个方向推导成功：该方向的模板更特殊。
- 两个方向都成功：C++20 起比较约束，更受约束者更特殊；约束也相同则不可比。
- 两个方向都不成功：不可比。
- 成员函数在转换后的模板中插入一个对象参数 `X(M)`，其引用种类由 ref 限定与另一模板的对应参数决定（[temp.func.order]/5）。
- 调用上下文只考虑有显式实参的形参；参数包、默认实参、省略号形参不参与偏序（[temp.func.order]/7）。

```cpp
template<class T> void f(T);
template<class T> void f(T*);

int* p = nullptr;
f(p); // 调用 f(T*)：更特殊

template<class T> void g(T);
template<class T> void g(T&);

float x = 0;
g(x); // 二义：两个方向都能推导
```

返回类型不参与偏序，也不参与重载决议。仅返回类型不同的函数模板不能构成有效重载。

### 6.6 约束偏序

两个模板的偏序无法区分时，比较关联约束（[temp.func.order]/2）。约束之间用包含（subsumption）关系比较：`P` 包含 `Q`，当且仅当 `P` 的每个析取子句都包含 `Q` 的每个合取子句；原子约束在规范化后相同才算包含（[temp.constr.order]/1）。

更受约束的模板胜出；互不包含则仍然不可比。

```cpp
template<class T> concept C1 = requires(T t) { --t; };
template<class T> concept C2 = C1<T> && requires(T t) { *t; };

template<C1 T> void f(T);
template<C2 T> void f(T);

f(0);        // C2 不满足，调用第一个
f((int*)0);  // 两者都满足，C2 更受约束，调用第二个
```

约束只影响可行性与偏序，不改变转换序列的排序。把适用条件写成约束，比写成返回类型或 `enable_if` 更直接，但约束的包含关系需要按规范化后的原子约束判断，不能按源码中的书写顺序推断。

### 6.7 决议失败的三种结果

排序结束后可能出现三种结果：

- 没有可行函数：调用 ill-formed，诊断通常为 no matching function。
- 没有一个函数优于所有其他可行函数：调用二义，诊断通常为 ambiguous。
- 唯一最优函数被删除或不可访问：决议本身成功，调用在后续检查处 ill-formed。

这三种结果对应不同修复方式。第一种要检查候选集是否漏掉声明、转换是否存在、约束是否满足；第二种要减少重载或让某个参数上的差异明确；第三种要处理删除或访问，继续调整重载无效。

## 7. 运算符的候选与改写

### 7.1 四类候选

运算符表达式的候选集由四部分组成（[over.match.oper]/3）：

| 来源 | 形成方式 | 例外 |
| --- | --- | --- |
| 成员候选 | 在左操作数类型 `T1` 中查找 `operator@` | `T1` 必须是完整类类型 |
| 非成员候选 | 非限定查找加 ADL，忽略成员函数 | `=`、`[]`、`->` 不产生非成员候选 |
| 内建候选 | [over.built] 定义的候选 | `,`、一元 `&`、`->` 没有内建候选 |
| 改写候选 | C++20 由关系、三路比较、相等运算符生成 | 其他运算符为空 |

成员候选只从左操作数类型产生，非成员候选对两个操作数都做查找。实参列表就是操作数；成员候选的左操作数对应隐式对象参数。

### 7.2 运算符查找与普通调用不同

运算符的名字查找与非限定函数调用不同：成员候选与命名空间候选分开收集，命名空间查找忽略成员函数（[over.match.oper]/3.2）。这解释了一个常见现象：在成员函数内部，成员运算符可以隐藏同名的全局运算符，但运算符表达式仍然能找到全局版本。

```cpp
struct A {};
void operator+(A, A);

struct B {
    void operator+(B);
    void f() {
        operator+(A{}, A{}); // 错误：成员 operator+ 隐藏全局名字
        A{} + A{};           // OK：运算符查找忽略成员，找到全局 operator+
    }
};
```

函数调用形式 `operator+(a, b)` 走普通非限定查找，成员函数隐藏外部名字；运算符形式 `a + b` 走 [over.match.oper] 的候选收集，成员候选只来自 `A`，而 `A` 没有成员 `operator+`，于是全局版本进入候选。

### 7.3 内建候选与转换限制

两个操作数都没有类或枚举类型时，运算符按内建运算符解释，不进行重载决议（[over.match.oper]/1）。只要有一个操作数是类或枚举类型，内建候选就与用户定义候选一起参与决议。

内建候选的转换有两条限制：

- 赋值运算符的左操作数只允许标准转换（[over.match.oper]/5）。因此不能通过用户定义转换把左操作数变成内建赋值可接受的类型。
- 内建候选被选中时，类类型操作数按选中函数的形参转换，但不应用用户定义转换序列的第二标准转换（[over.match.oper]/11）。

第二条限制保证内建运算符拿到的是转换函数的结果本身，不再做一次额外调整。例如两个分别转换为 `double` 与 `int*` 的对象相加，内建候选可能因指针算术要求整数操作数而报错。

### 7.4 改写候选

C++20 引入改写候选（rewritten candidate），让 `<=>` 与 `==` 能覆盖其他比较运算符（P1185R2）。候选生成规则如下（[over.match.oper]/3.4）：

- 关系运算符 `<`、`>`、`<=`、`>=`：加入 `x <=> y` 的非改写候选，以及参数反转的 `y <=> x` 合成候选。
- 三路比较 `<=>`：加入参数反转的合成候选。
- `!=`：加入 `x == y` 中可作为 rewrite target 的非改写候选，以及参数反转的 `y == x` 合成候选。
- `==`：加入参数反转的 `y == x` 合成候选。

改写候选被选中后，表达式按固定形式解释（[over.match.oper]/9、/10）：

- 关系运算符选中 `<=>` 候选时，`x @ y` 解释为 `(x <=> y) @ 0`；反转候选解释为 `0 @ (y <=> x)`。`<=>` 自身的反转候选也按 `0 @ (y <=> x)` 解释。
- `!=` 选中 `==` 候选时，解释为 `!(x == y)`；反转候选解释为 `!(y == x)`。
- `==` 选中反转候选时，解释为 `y == x`。

改写 `==` 候选被选中时，返回类型必须是 cv `bool`；不满足时程序 ill-formed（[over.match.oper]/10）。

```cpp
struct S {
    bool operator==(const S&) const;
};

S a, b;
bool x = a != b; // 改写为 !(a == b)
```

```cpp
struct T {
    friend auto operator<=>(const T&, const T&) = default;
};

bool y = T{} < T{}; // 改写为 (T{} <=> T{}) < 0
```

反向候选让不同操作数顺序都能匹配。下面的模板 `operator==(A, T)` 可以通过反转候选处理 `0 == A()`：

```cpp
struct A {};
template<class T> bool operator==(A, T);

bool z = 0 == A(); // 反转候选：A() == 0
```

改写不是无条件的。标准要求 `operator==` 是 rewrite target：如果在相应作用域中能找到与它对应的 `operator!=`，则 `operator==` 不用于改写 `!=`（[over.match.oper]/4）。这条限制由 P2468R2 加入，避免已有 `operator!=` 的类型因为 `==` 的改写而改变语义。

平局时，原始候选优于改写候选，非反转候选优于反转候选（[over.match.best.general]/2.8、/2.9）。因此同时定义 `operator<` 与 `operator<=>` 时，`a < b` 优先调用 `operator<`。

## 8. 初始化、取地址与 CTAD

### 8.1 初始化形式与候选集

同一个构造函数在不同初始化形式下的候选集不同：

| 形式 | 候选 | 说明 |
| --- | --- | --- |
| `T x(args);` | 全部构造函数 | 直接初始化 |
| `T x = expr;` | 非 explicit 构造函数与转换函数 | 拷贝初始化，explicit 不参与 |
| `T x{args};` | 两阶段列表初始化 | 直接列表初始化 |
| `T x = {args};` | 两阶段列表初始化 | 拷贝列表初始化，选中 explicit 时 ill-formed |
| `f({args})` | 列表初始化序列 | 实参本身是初始化列表 |

`static_cast<T>(expr)` 按直接初始化处理。`T x = expr` 中的 `expr` 先转换为 `T`，转换可能通过构造函数，也可能通过转换函数，但只允许一次用户定义转换。

```cpp
struct A {
    explicit A(int);
};

A a(1);  // 直接初始化，A(int)
A b = 1; // 错误：explicit A(int) 不在拷贝初始化的候选集
```

### 8.2 直接引用绑定

引用初始化可以直接绑定到转换函数的结果，这时候选转换函数由 [over.match.ref] 选择。非 explicit 转换函数的返回类型必须与目标引用类型引用兼容；直接初始化时，explicit 转换函数在结果只差限定转换时也可用。

对函数类型引用，平局规则 2.3 会区分返回左值引用与返回右值引用的转换函数：

```cpp
template<class T>
struct R {
    operator T&();
    operator T&&();
};

using Fn = int();
R<Fn> r;
Fn& lf = r;        // operator T&
Fn&& rf = R<Fn>{}; // operator T&&
```

### 8.3 取重载集地址

取重载集地址不按实参排序，而按目标类型选择（[over.over]/1）。没有目标类型时，只选择非模板函数；有目标类型时，对每个函数模板做推导，加入推导成功的特化，再消去约束不满足者、非模板优先、更特殊的模板优先，最后必须恰好剩一个函数（[over.over]/2 至 /5）。

```cpp
int f(int);
int f(double);

int (*p)(int) = &f;   // 选择 f(int)
auto q = &f;          // 错误：没有目标类型，无法在重载集中选择
```

没有目标类型时也可以用显式转型提供目标：

```cpp
auto p = static_cast<int (*)(int)>(&f);
```

### 8.4 类模板实参推导

CTAD 复用重载决议：候选是类模板的构造函数与推导指引（deduction guide），实参是初始化器，选出最优候选后确定类模板实参，再用选中的构造函数初始化对象（[over.match.class.deduct]）。

```cpp
std::pair p{1, 2.0}; // pair<int, double>
```

CTAD 另有几条平局规则（[over.match.best.general]/2.10 至 /2.13）：非继承构造函数优先于继承构造函数；推导指引优先于非指引；拷贝推导候选优先；非模板构造函数优先于构造函数模板。这些规则只在 CTAD 内部使用，不影响普通函数调用的排序。

## 9. 显式对象参数

C++23 引入显式对象参数（explicit object parameter），允许把对象参数写进形参列表（P0847R7）：

```cpp
struct S {
    void f(this S& self);
    void f(this S&& self);
};
```

这类成员函数没有隐式对象参数。对象实参仍然作为第一个实参参与匹配，但它对应显式声明的参数，按普通实参规则处理。因此下面两点与隐式对象参数不同：

- 允许用户定义转换。对象实参可以通过转换函数变成对象参数的类型（[over.best.ics.general]/9 注）。
- 对象参数参与模板推导。模板化的显式对象参数可以从对象实参推导出类型、cv 限定与值类别。

```cpp
struct T {
    operator int() const;
    void g(this int);
};

T t;
t.g(); // 对象实参 T → int，使用用户定义转换
```

显式对象参数本身携带 cv 与引用限定，函数声明上不能再写 `const` 或 ref 限定。重载可以按对象参数的类型与值类别区分：

```cpp
struct U {
    void h(this U&);
    void h(this U&&);
};

U u;
u.h();    // U&
U{}.h();  // U&&
```

模板版本可以在一处保留对象的值类别：

```cpp
struct V {
    template<class Self>
    void k(this Self&& self);
};

V v;
v.k();              // Self = V&
std::move(v).k();   // Self = V
const V cv{};
cv.k();             // Self = const V&
```

显式对象成员函数不能声明为 `static`，函数体内没有 `this`，需要使用参数名。它可以匹配函数指针目标；非成员函数、静态成员函数与显式对象成员函数都按函数指针类型匹配（[over.over]/4）。

## 10. 诊断与工程实践

### 10.1 读诊断

重载决议失败的诊断通常分三段：调用点、候选列表、每个候选被淘汰或不被选中的原因。常见文本与含义如下：

| 诊断 | 含义 | 检查方向 |
| --- | --- | --- |
| no matching function | 没有可行函数 | 候选集、参数个数、转换、约束 |
| ambiguous | 没有唯一最优候选 | 逐参数比较，找出分歧点 |
| call to deleted function | 最优候选被删除 | 删除声明或调整实参类型 |
| private member | 最优候选不可访问 | 访问控制，不是重载问题 |

GCC、Clang、MSVC 都会列出候选及其转换结果，但顺序与详细程度不同。定位时可以先看候选是否在集合里，再看每个实参到形参的转换，最后看平局规则。

`decltype` 与 `static_assert` 可以把选择结果变成编译期检查：

```cpp
static_assert(std::is_same_v<decltype(f(1)), int>);
```

对二义调用，显式转换实参或显式指定模板实参通常能暴露真正想要的重载。直接把返回值赋给目标类型不能解决重载二义，因为返回类型不参与决议。

### 10.2 设计准则

1. 让重载在形参类型上可分。仅靠返回类型、约束或函数体差异区分重载，无法形成有效重载集。
2. 单参数构造函数与转换函数默认加 `explicit`。隐式转换会增加候选，也会让调用点难以定位。
3. 避免无约束的万能引用。`template<class T> void f(T&&)` 对多数实参都是精确匹配，容易压过更具体的重载；需要时用约束限定适用范围。
4. 运算符优先写成非成员或隐藏友元，让两侧操作数都能参与转换。成员运算符要求左操作数是类类型。
5. 不要依赖删除函数「不参与决议」。删除函数仍可能压过更差的可行候选；需要用删除排除调用时，确保这是想要的效果。
6. 访问权限不改变决议结果。把更匹配的重载设为私有，只会让调用在访问检查处失败。
7. 取重载集地址时给出目标类型。`auto p = &f` 在存在多个重载时无法推导。
8. 列表初始化与圆括号初始化语义不同。`{}` 优先选择 `initializer_list` 构造函数，`()` 按普通构造函数匹配。
9. 约束用于表达适用条件，不要用它替代偏序排序。两个约束互不包含时，调用仍然二义。
10. 跨翻译单元保持声明一致。重载集、默认实参与约束都属于声明的一部分，ODR 违规通常不诊断。

### 10.3 常见误用

| 写法 | 结果 | 原因 | 修正 |
| --- | --- | --- | --- |
| `void f(int); void f(double) = delete; f(1.0)` | 调用 deleted | 删除函数参与决议 | 删除声明或改实参类型 |
| 私有重载更匹配 | 访问错误 | 访问在决议之后 | 调整可见性 |
| `f(0)` 同时有 `bool` 与 `void*` 重载 | 二义 | 布尔转换与指针转换同级 | 传 `nullptr` 或显式类型 |
| `std::vector<int> v{10, 20}` | 两个元素 | `initializer_list` 优先 | 需要个数与初值时用 `()` |
| 仅返回类型不同的两个函数 | 无法重载 | 返回类型不参与决议 | 改形参或函数名 |
| `auto p = &f` 且 `f` 重载 | 无法取地址 | 没有目标类型 | `static_cast` 指定函数指针类型 |
| 无约束的 `T&&` 重载 | 抢占其他重载 | 精确匹配范围过宽 | 加约束或改用具体类型 |
| 仅定义 `operator==` 后使用 `!=` | C++20 可改写，C++17 报错 | 改写候选是 C++20 特性 | 补 `operator!=` 或升级标准 |

## 11. 版本演进

| 版本 | 主要变化 | 对决议的影响 |
| --- | --- | --- |
| C++98 | 基本的三步模型 | 没有右值引用、ref 限定、列表初始化与显式转换函数 |
| C++11 | 右值引用、ref 限定、删除与默认函数、显式转换函数、`initializer_list` | 增加引用绑定平局、列表初始化序列与删除候选 |
| C++17 | 保证复制消除、继承构造函数改写 | 临时对象与继承构造的候选行为更明确 |
| C++20 | 概念与约束、改写候选、`explicit(bool)` | 增加约束可行性与偏序、运算符改写 |
| C++23 | 显式对象参数、静态 `operator()` 与 `operator[]` | 对象参数可以显式声明并参与推导 |

C++11 的变化最集中：右值引用让引用绑定成为排序的一部分，ref 限定让成员函数的对象参数可以区分左值与右值，`initializer_list` 让列表初始化有了独立的两阶段选择，删除函数让「参与决议但不可调用」成为一种正式写法。

C++20 的变化改变了候选集本身。改写候选让一个 `operator<=>` 可以服务四个关系运算符，约束让候选的可行性可以在模板之外表达，约束偏序又给模板平局增加了新的裁决层。

C++23 的显式对象参数把对象参数从隐式变为显式。它不改变三步模型，但改变了对象实参的匹配方式：用户定义转换重新被允许，模板推导可以作用在对象参数上。

## 12. 结论

重载决议可以压缩成一条链：名字查找给出候选，模板推导把模板变成候选，约束与参数个数筛出可行函数，隐式转换序列逐参数比较，平局规则在不可比处裁决。

容易混淆的地方集中在几个分界。第一，候选集与可行性：名字查找决定「有哪些」，决议只决定「选哪个」。第二，可行性与可用性：删除、访问、位域绑定、窄化等限制可能在决议之后才报错。第三，偏序与全序：转换序列与模板偏序都只给出偏序，互不逊色就是二义，不存在隐藏的评分。

工程上最有效的做法是减少重载之间的隐式转换：让形参类型明确，让单参数构造函数与转换函数默认 `explicit`，给模板重载加约束，给运算符重载保持对称。这样既减少二义，也让诊断更容易读。
