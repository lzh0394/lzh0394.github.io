## 1. 定义

modulo（模运算）是求「一个数除以另一个数的余数」的二元运算，第二个操作数称为模数（modulus）。

给定两个正数 a 和 m，`a mod m` 是 a 除以 m 的欧几里得除法余数：a 是被除数，m 是除数。例如 `5 mod 2 = 1`（商 2 余 1），`9 mod 3 = 0`（整除）。

整数情形下几位约定俗成的性质：

- 结果范围是 0 到 m - 1（含两端），前提是两个操作数都是正数。
- `a mod 1 = 0`，对任意整数 a 成立。
- 当 a 或 m 恰好有一个为负时，「基本定义」就失效了——此时各编程语言给出不同答案，这正是模运算最容易踩坑的地方。

维基条目特别指出：多数系统虽然按整数处理，但如今也允许其他数值类型（浮点）。浮点取模通常由 `fmod` 一类库函数承担，且约定可能又是另一套。

## 2. 数学上的 `a mod m` 是等价类

严格来说，数学里的 `a mod m` 不是一个数，而是一个等价类，类里任何成员都可以选作代表元。常用代表元是最小正剩余（least positive residue），即该类中最小的非负整数——也就是欧几里得除法的余数。

例如 `11 mod 3` 严格讲不等于 2，而是集合：

```text
{..., -4, -1, 2, 5, 8, 11, 14, ...}
```

即所有与 2 关于模 3 同余的整数，通常记作 `[2]`。

注意与同余记号的区分：`a ≡ b (mod m)` 是同余关系，说的是两个数之差被 m 整除；而 `a mod m` 是二元运算，产出的是一个数（或上述代表元约定下的一个数）。模运算的记法通常写作 `mod(a, m)`，或用 `%`、`mod`、`Mod` 之类的运算符。

---

## 3. quotient 与 remainder 的通用条件

几乎所有计算系统里，a 除以 n（n ≠ 0）的商 q 与余数 r 都满足：

```text
q ∈ Z
a = n*q + r
|r| < |n|
```

这三条不足以唯一确定 r。当 r 非零时总有两种选择（一正一负），选了哪个余数，就决定了必须配哪个相邻的商。

- 数论里永远取正余数。
- 计算领域则看语言：标准 Pascal、ALGOL 68 即使除数为负也给正余数（或 0）；C90 在 n 或 a 为负时把选择权交给实现（implementation-defined）；也有系统把 `a mod 0` 留作未定义，另有系统定义成 `a`。

于是「如何定义商」分出了几种流派，取值结果随之不同。

## 4. 五种除法约定

| 约定 | 商 q | 余数 r | r 的符号 |
| --- | --- | --- | --- |
| 截断 truncated | trunc(a/n)（向零取整） | a - n·trunc(a/n) | 与被除数 a 同号 |
| 向下取整 floored | ⌊a/n⌋ | a - n·⌊a/n⌋ | 与除数 n 同号 |
| 欧几里得 Euclidean | sgn(n)·⌊a/\|n\|⌋ | a - n·q，且要求 0 ≤ r < \|n\| | 恒非负 |
| 四舍五入 rounded | round(a/n)（银行家舍入） | a - n·round(a/n) | 落在 -n/2 与 n/2 之间，看靠哪边 |
| 向上取整 ceiling | ⌈a/n⌉ | a - n·⌈a/n⌉ | 与除数 n 反号 |

各约定的代表语言：

- 截断：C、C++、Java、Go、Rust、JS
- 向下取整：Python、Ruby、Lua 5、Perl、MATLAB `mod`
- 欧几里得：Ada `mod`、Dart、R⁶RS `mod`、Maple
- 四舍五入：IEEE 754 `remainder`、Common Lisp、C# `Math.IEEERemainder`
- 向上取整：Common Lisp

欧几里得定义的等价写法是先用 `sgn(n)` 归正除数再向下取整：

```text
q = sgn(n) * floor(a / |n|)
  = floor(a/n)   若 n > 0
  = ceil(a/n)    若 n < 0
r = a - |n| * floor(a / |n|)
```

注意 truncated 有一个别的定义不具备的好性质：`(-a)/b = -(a/b) = a/(-b)`。这也是 C 系语言选它的一个理由。

### 4.1 什么时候几种定义一致

- 被除数与除数都为正 → 五种（至少前三种）结果相同。
- 被除数为正、除数为负 → 截断与欧几里得一致。
- 被除数为负、除数为正 → 向下取整与欧几里得一致。
- 被除数与除数都为负 → 截断与向下取整一致。

也就是说，只要不出现负数，这些分歧根本不存在；一旦涉负，选哪种约定就成了语言规范的一部分。

## 5. 对照表：同一个式子，五种答案

以 a、n 取不同符号为例（q 为商，r 为余数）：

| a | n | 截断 r (q) | 向下取整 r (q) | 欧几里得 r (q) |
| --- | --- | --- | --- | --- |
| 5 | 2 | 1 (2) | 1 (2) | 1 (2) |
| -5 | 2 | -1 (-2) | 1 (-3) | 1 (-3) |
| 5 | -2 | 1 (-2) | -1 (-3) | 1 (-2) |
| -5 | -2 | -1 (2) | -1 (2) | 1 (3) |
| 7 | -3 | 1 (-2) | -2 (-3) | 1 (-2) |
| -7 | -3 | -1 (2) | -1 (2) | 2 (3) |
| 5 | 3 | 2 (1) | 2 (1) | 2 (1) |
| -5 | 3 | -2 (-1) | 1 (-2) | 1 (-2) |

四舍五入与向上取整：

| a | n | 四舍五入 r (q) | 向上取整 r (q) |
| --- | --- | --- | --- |
| 5 | 2 | 1 (2) | -1 (3) |
| -5 | 2 | -1 (-2) | -1 (-2) |
| 5 | -2 | 1 (-2) | 1 (-2) |
| -5 | -2 | -1 (2) | 1 (3) |
| 7 | -3 | 1 (-2) | 1 (-2) |
| -7 | -3 | -1 (2) | 2 (3) |
| 5 | 3 | -1 (2) | -1 (2) |
| -5 | 3 | 1 (-2) | -2 (-1) |

从表里能看出两条规律：截断的余数符号跟着被除数走，向下取整的余数符号跟着除数走，欧几里得的余数永远非负。

## 6. C / C++ 里 `%` 的确切语义

标准草案 [\[expr.mul\]](https://eel.is/c++draft/expr.mul) 对整型操作数的规定：

- `/` 给出「丢弃小数部分的代数商」，脚注点明这就是向零截断（truncation towards zero）。
- 若商 `a/b` 在结果类型中可表示，则 `(a/b)*b + a%b == a`；否则 `a/b` 与 `a%b` 的行为都是未定义。
- `/` 或 `%` 的第二个操作数为 0 时行为未定义（[\[ub:expr.mul.div.by.zero\]](https://eel.is/c++draft/ub:expr.mul.div.by.zero)）。

由此得到 C++ 的取模语义：余数与被除数同号，即截断约定。`-5 % 2` 是 -1，不是 1。

版本差异必须分清：

- C++11 起（及 C99 起）明确为向零截断，`%` 的符号规则是语言保证。
- C++11 之前（C++03、C90）：两个操作数都非负时余数非负；否则余数符号是实现定义（implementation-defined）。所以老代码里 `-5 % 2` 理论上可能是 -1，也可能是 1，取决于编译器。

另外 C++ 的 `%` 的操作数只能是整型或无作用域枚举（`*`、`/` 允许算术类型），浮点取模要用 `std::fmod`（截断式），IEEE 754 取余数用 `std::remainder`（四舍五入式）。

`INT_MIN % -1` 属于上面「商不可表示」的情形，是 UB——它和除零一样是 `%` 的雷区。

## 7. 常见陷阱

### 7.1 判奇偶不能写 `n % 2 == 1`

在余数随被除数符号的语言里（C、C++、Java、Go、Rust、JS……），负数奇数的 `n % 2` 得到 -1，这个判断会漏掉所有负奇数：

```cpp
// 错：n = -3 时 -3 % 2 == -1，函数返回 false
bool is_odd(int n) { return n % 2 == 1; }

// 对：0 与符号无关
bool is_odd(int n) { return n % 2 != 0; }

// 也可以走位运算
bool is_odd(int n) { return n & 1; }
```

### 7.2 想把结果变成非负，要随机应变

需要「模结果落在 [0, n)」时，在截断语义下通常要补一次修正：先取模，若为负再加模数。如果除数是常量、且希望编译器有机会优化，也可直接用无符号算——无符号的取模天然就是非负的。

### 7.3 除数为 0

数学上不成立；C++ 里是 UB；不少语言抛异常；也有系统干脆定义成 `a`。跨语言移植时不要假设。

## 8. 性能：2 的幂可以换成位与

取模在硬件上往往要真做一次带余除法，比较贵。对 2 的幂有等价替换：

```text
x % 2^n  ==  x & (2^n - 1)
```

例如 `x % 2 == x & 1`、`x % 4 == x & 3`、`x % 8 == x & 7`。在位运算比取模便宜的机器上，这样写更快。

编译器也会自动做这个优化：识别 `表达式 % 常量`（常量为 2 的幂）并改写成位与，于是程序员可以写更清楚的代码。

但这个优化在 C 这类余数随被除数符号的语言里对通用表达式不成立——被除数为负时取模结果是负的，而 `x & (2^n - 1)` 永远是正的。除非被除数是无符号类型。要等价就得用条件式：

```text
x % 2^n == (x < 0) ? (x | ~(2^n - 1)) : (x & (2^n - 1))
```

一般常量的取模优化则走另一条路：先用「除以常数」的算法算出商，再回头求余。

## 9. 恒等式

以下性质在密码学证明（如 Diffie–Hellman 密钥交换）里很有用。涉及乘、除、幂的那些一般要求 a、n 都是整数。

- 幂等：`(a mod n) mod n == a mod n`
- `n^x mod n == 0`，x 为正整数
- 费马小定理：p 为素数且不整除 b 时，`a*b^(p-1) mod p == a mod p`
- 相反数：`[(-a mod n) + (a mod n)] mod n == 0`
- 乘法逆元 `b^(-1) mod n` 存在当且仅当 b 与 n 互素；此时 `[(b^(-1) mod n)(b mod n)] mod n == 1`
- 加法可分配：`(a + b) mod n == [(a mod n) + (b mod n)] mod n`
- 乘法可分配：`(a*b) mod n == [(a mod n)(b mod n)] mod n`
- 除法（定义式）：`(a/b) mod n == [(a mod n)(b^(-1) mod n)] mod n`，当且仅当右边有定义（即 b、n 互素），否则无定义
- 逆元消去：`[(a*b mod n)(b^(-1) mod n)] mod n == a mod n`

## 10. 推广与换算

### 10.1 带偏移的取模

有时希望结果落在 `[d, d + n - 1]` 而不是 `[0, n - 1]`，d 称为偏移量，`d = 1` 尤其常见（比如把 0 基下标换成 1 基）。没有标准记号，维基条目临时写作 `a mod_d n`，定义为：

```text
d <= x <= d + n - 1  且  x mod n == a mod n
```

它与取整函数的关系是：

```text
a mod_d n = a - n * floor((a - d) / n)
```

零偏移即退化为普通取模：`a mod n == a mod_0 n`。Mathematica 用 `Mod[a, n, d]` 实现这个运算。

### 10.2 用截断实现其他定义

尽管向下取整与欧几里得在数学上更优雅，语言里最常见的仍是截断。Leijen 给出的换算算法（用 C 写，风格仿 `ldiv()`）：

```c
/* Euclidean and Floored divmod, in the style of C's ldiv() */
typedef struct {
  long int quot;
  long int rem;
} ldiv_t;

/* Euclidean division */
inline ldiv_t ldivE(long numer, long denom) {
  /* The C99 and C++11 languages define both of these as truncating. */
  long q = numer / denom;
  long r = numer % denom;
  if (r < 0) {
    if (denom > 0) {
      q = q - 1;
      r = r + denom;
    } else {
      q = q + 1;
      r = r - denom;
    }
  }
  return (ldiv_t){.quot = q, .rem = r};
}

/* Floored division */
inline ldiv_t ldivF(long numer, long denom) {
  long q = numer / denom;
  long r = numer % denom;
  if ((r > 0 && denom < 0) || (r < 0 && denom > 0)) {
    q = q - 1;
    r = r + denom;
  }
  return (ldiv_t){.quot = q, .rem = r};
}
```

两个函数里余数都可以脱离商单独算；反过来商不能脱离余数单独算，所以这里把两者一起返回，顺便共用同一个分支判断。
