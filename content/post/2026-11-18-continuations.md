> 范围：从续延的定义与 CPS、`call/cc` 两种表示出发，对照 C++20 协程、异常与代数效应，最后给出语言特性的谱系与实现代价。条款引用以 C++26 最终草案 N5050 为准，C++20 措辞用 N4861 对照；提案以 WG21 编号标注，实现细节以 Itanium C++ ABI 与 OCaml 5 的实现说明为准。

## 0. 结论摘要

1. 续延是「程序在某一点之后剩余的计算」被具体化为可调用的值，捕获点、剩余计算与调用方式构成三个要素。
2. 按续延传递风格（continuation-passing style，CPS）写代码时续延是显式参数；`call/cc` 把它变成语言原语。两者的差别在捕获范围、调用次数与恢复方向。
3. 一次性续延可以原地转移，多次续延需要复制或保留栈，两者的开销差距明显。
4. C++20 协程把「从挂起点到协程结束」的剩余计算放进协程状态，句柄是这段计算的一等引用；它是有界、一次性、无栈的续延。
5. 对称转移把恢复下一个协程变成尾调用，恢复链的栈深度保持常数。
6. 异常是单向的逃逸续延：处理器由动态查找确定，栈展开后抛出点的现场不再保留。
7. 异常不会自动穿过挂起点，C++20 协程用 `unhandled_exception` 保存异常，在 `await_resume` 中重抛。
8. 代数效应在定界续延之上按操作名分派，处理器可以调用续延零次、一次或多次，异常与 `call/cc` 都是它的特例。
9. 实现代价集中在多次续延的栈复制与指针重定位；尾恢复的一次性处理器开销接近普通函数调用。
10. 语言特性按捕获范围、次数、方向、是否一等四个维度排成谱系，每一档都是对续延能力的削减。

## 1. 剩余计算

### 1.1 从表达式看续延

对表达式 `1 + 2 * f(x)`，求值到 `f(x)` 时，剩余部分是「把结果乘以 2 再加 1」。把这部分写成函数：

```text
k = λv. 1 + 2 * v
```

`k` 就是该点的续延（continuation）。`f` 把结果交给 `k`，求值仍然完成，只是「返回」这个动作消失了。

普通函数的「之后做什么」藏在返回地址与调用栈里，程序无法读取。续延把这个上下文变成值，于是它可以被保存、传递、丢弃、调用多次。

### 1.2 三个要素

任何续延的实现都要回答三个问题：

- 捕获点在哪里：整个调用栈、某个定界符之内，还是只到函数返回。
- 剩余计算包含什么：代码位置，加上仍然存活的状态。
- 如何调用：跳转，还是恢复一组栈帧。

第四个问题随之而来：能调用几次。四个问题的答案组合出全部变体。

### 1.3 续延传递风格

CPS 是把续延显式化的写法：每个函数多接收一个续延参数，结果通过调用它传出，函数本身不再返回。

```text
f(k) = g(λv. k(use(v)))
```

调用 `f(k)` 之后，控制流最终到达 `k`，中间的函数只做尾调用。CPS 的代价是每个调用点多一次间接调用与一个闭包，收益是控制流完全显式，编译器与程序员都能操纵它。

### 1.4 捕获与调用

CPS 需要手工传递续延。语言原语把当前上下文直接捕获成一等值，典型是 Scheme 的 `call/cc`：

```scheme
(define (find pred lst)
  (call/cc
    (lambda (return)
      (for-each (lambda (x) (if (pred x) (return x))) lst)
      #f)))
```

`return` 捕获「`find` 返回之后」的续延。在 `for-each` 内部调用它，控制流直接回到 `find` 的调用点，效果等于提前返回。

`call/cc` 捕获到程序结束为止，调用之后不会回到捕获点，因此两个续延无法嵌套组合。有界续延（delimited continuation）用 `reset` 划定边界、用 `shift` 捕获边界内的部分，捕获到的续延可以返回，也可以组合，这是后面代数效应的基础。

## 2. 一次与多次

### 2.1 一次性与多次

续延能否反复调用，决定了实现方式：

| 类型 | 含义 | 实现代价 |
| --- | --- | --- |
| 一次性（one-shot） | 调用一次后失效 | 可原地转移栈帧，开销小 |
| 多次（multi-shot） | 可反复调用，每次重放 | 需要复制栈或使用不可变帧 |

多数语言只提供一次性续延。原因是多次续延与可变状态、资源释放冲突：同一段清理代码可能执行两次，同一把锁可能被释放两次。Scheme 的实现允许多次调用，代价是栈必须可复制，且与 C 的互操作受限。

### 2.2 复制与重定位

复制栈不只是搬运字节。栈帧里存有指向栈内的指针，复制之后这些指针仍指向旧栈，必须逐帧修正。修正的前提是运行时知道哪些字是指针，也就是精确的栈映射（stack map）。保守式垃圾回收无法区分指针与整数，复制后的栈就会悬垂。

这条限制解释了为什么多数工业实现选择一次性续延：一次性续延可以原地转移，不需要复制，也就不需要栈映射。

## 3. C++20 协程

### 3.1 帧与句柄

函数体出现 `co_await`、`co_yield` 或 `co_return` 时，函数成为协程（`[dcl.fct.def.coroutine]`/1）。返回类型经 `std::coroutine_traits` 找到 `promise_type`。编译器把函数体替换成一段等价代码（replacement body，`[dcl.fct.def.coroutine]`/5），并把跨挂起点仍然存活的状态放进协程状态（coroutine state，`[dcl.fct.def.coroutine]`/9）。

标准允许实现省略协程状态的分配，但不保证。返回对象由 `get_return_object` 生成，在 `initial_suspend` 之前交给调用者（`[dcl.fct.def.coroutine]`/7）。

协程状态通常包含 promise 对象、参数副本、局部变量、跨挂起点的临时量、挂起位置与恢复入口。帧的实际布局由实现决定，标准只规定可观察行为。

`std::coroutine_handle` 是指向帧的句柄，`resume()` 从当前挂起点继续执行，`destroy()` 销毁帧。句柄本身不携带返回值，值要经 promise 传递。任务的构造细节见[《C++20 协程的语言机制》](/post/2026/11/18/cpp20-coroutines/)。

### 3.2 与 CPS 的对应

| CPS 概念 | C++20 协程 |
| --- | --- |
| 续延值 `k` | `coroutine_handle` |
| 调用 `k(v)` | `resume()`，值经 promise 传出 |
| 捕获自由变量 | 跨挂起点的变量提升进帧 |
| 尾调用 | 对称转移 |
| 定界符 | 协程体结束处的 `final_suspend` |

`co_await` 的求值顺序由 `[expr.await]`/5 规定：先取 await-ready 的值，为假时协程挂起，再求值 await-suspend；协程恢复后调用 await-resume，其结果就是表达式的值。

`await_suspend` 接收当前协程的句柄，把它交给异步操作，这一步等价于把续延当参数传出去。`await_resume` 把结果送进续延，等价于 `k(v)`。

### 3.3 对称转移

被等待的协程结束时，控制权应当交给等待者。普通写法是在 `final_suspend` 里调用等待者的 `resume()`，每次恢复都压一层调用栈，链一长就会耗尽栈空间。

对称转移把这件事变成返回值：若 await-suspend 表达式的结果类型是 `std::coroutine_handle<Z>`，标准规定求值 `await-suspend.resume()`（`[expr.await]`/5.1.1），当前协程保持挂起，控制权直接交给目标协程。实现上这是一次尾调用，当前帧不再保留。

```cpp
struct final_awaiter {
  bool await_ready() noexcept { return false; }

  std::coroutine_handle<>
  await_suspend(std::coroutine_handle<promise> h) noexcept {
    auto c = h.promise().continuation;
    return c ? c : std::noop_coroutine();
  }

  void await_resume() noexcept {}
};
```

`continuation` 在等待时由等待者的 awaiter 写入，`noop_coroutine()` 用作没有续接者时的安全目标。恢复链的栈深度由此保持常数。

### 3.4 受限之处

C++20 协程是续延的一个受限实现，限制有四条：

- 有界。捕获范围止于协程体，普通函数调用链中途无法挂起。await 表达式只能出现在函数体或 lambda 体内（`[expr.await]`/2），这就是无栈（stackless）的含义。
- 一次性。`resume()` 的前置条件要求协程处于挂起状态，且不在最终挂起点（`[coroutine.handle.resumption]`/2），违反前置条件是未定义行为。
- 单向。续延被恢复后不会回到发起恢复的调用点，除非那条链由对称转移接回去。
- 类型擦除。`std::coroutine_handle<>` 只保留恢复与销毁能力，句柄不携带值，值必须经 promise 传递。

## 4. 异常

### 4.1 逃逸续延

`try { body } catch (E e) { h(e) }` 在语义上等价于用 `call/cc` 安装一个转义续延：

```text
call/cc(λk. body[throw e ↦ k(h(e))])
```

`try` 在动态上下文中安装 `k`，`throw` 调用它。差别在于这个 `k` 是一次性的逃逸续延：调用之后抛出点的现场已经销毁，无法再回来。

处理器的位置由调用栈在运行期确定，与词法位置无关。`catch` 拿到的是异常对象，抛出现场不在其中。异常对象是这条单向通道能携带的全部信息。

### 4.2 栈展开

标准把从抛出点到处理器的过程定义为栈展开（stack unwinding）：控制权经过的每个作用域，自动对象按构造的逆序销毁（`[except.ctor]`/1、`[except.ctor]`/2）。

常见实现分两阶段：

1. 搜索阶段沿栈回溯，用异常表判断哪一帧有匹配的处理器，只读不写。
2. 展开阶段从抛出点走到处理器，逐帧调用析构函数。

两阶段把「找到处理器」与「销毁现场」分开。展开过程中析构函数抛出异常时，程序终止。Windows 的结构化异常与 Itanium ABI 都采用这个结构。

### 4.3 值与跳转的分界

`std::exception_ptr` 可以把异常保存下来，在另一个上下文重新抛出。`current_exception` 捕获，`rethrow_exception` 重抛。这一步把一次性跳转冻结成可再次投递的值，异常因此能跨线程、跨回调边界传递。

`nested_exception` 处理「处理失败时再次失败」，把内层异常挂在对外抛出的异常上。两者都没有恢复现场的能力，只是在单向通道上增加携带的信息。

### 4.4 与协程的交叉

挂起点把异常的处理位置与抛出位置拆开。C++20 协程的规则是异常不穿过挂起点自动传播：协程体内的异常交给 `unhandled_exception`，通常保存为 `std::exception_ptr`，协程进入最终挂起点；等待者恢复后，在 `await_resume` 中重抛。

```cpp
void unhandled_exception() { error_ = std::current_exception(); }

void await_resume() {
  if (error_) std::rethrow_exception(error_);
}
```

异常在等待者的上下文重新抛出，沿等待者的调用链传播。标准要求 `final_suspend` 的表达式不是潜在抛出的（`[dcl.fct.def.coroutine]`/15），因为那时已经没有可用的处理路径。

### 4.5 可恢复的形式

异常不可恢复，但同一问题有更强的形式。Common Lisp 的条件系统让处理器在栈尚未展开时运行，由它选择继续、重试或跳转，这就是可恢复异常。契约的 continuation mode 把「处理函数返回之后是否继续」显式化：`off` 之下终止，`on` 之下继续执行。

这些机制都在回答同一个问题：处理器执行完之后，控制流回到哪里。异常的选择是不再回到抛出点，可恢复形式则回到抛出点或指定的恢复点。

## 5. 代数效应

### 5.1 操作与处理器

代数效应（algebraic effects）把操作的声明与解释分开。代码只声明要执行什么操作，外层处理器决定该操作的含义，并拿到操作点之后的续延。

```text
effect State {
  get() : Int
  put(Int) : Unit
}

let f = {
  let n = get()
  put(n + 1)
  n
}

handle f with {
  return v -> v
  get()    -> resume(s, s)
  put(s')  -> resume((), s')
}
```

`resume` 是操作点之后的续延，处理器把状态放在自己的闭包里，恢复时把当前值传回去。调用方看不到状态，`f` 也不需要接受状态参数。

### 5.2 续延的三种用法

处理器的表达力来自调用续延的次数：

| 调用续延 | 语义 | 对应机制 |
| --- | --- | --- |
| 零次 | 放弃剩余计算 | 异常、失败、短路 |
| 一次 | 继续执行 | 状态、日志、`async`/`await`、生成器 |
| 多次 | 重放剩余计算 | 非确定性搜索、回溯、概率采样 |

非确定性最能体现差别：

```text
handle choose() with {
  choose() -> resume(true) ++ resume(false)
}
```

每次 `choose()` 都把同一段后续计算跑两遍，结果合并成列表。异常做不到这一点，因为跳转之后后续计算已经销毁。

按这个框架，`raise` 是零次调用续延的处理器，`call/cc` 是能多次调用续延的处理器，两者的区别只在次数。

### 5.3 「代数」的含义

操作集合构成一个代数签名（signature）：每个操作有参数类型与结果类型，通常还带方程。状态效应满足 `put(s); get() = s` 一类的定律。处理器是从自由代数到某个模型的同态，满足方程的解释才是合法的处理器。

方程约束了处理器的行为，使它不能任意解释操作；它同时决定处理器之间何时可以视为等价。

### 5.4 深与浅

- 深层处理器（deep handler）：恢复续延时，处理器仍然包裹后续计算，处理范围延伸到剩余部分。
- 浅层处理器（shallow handler）：只处理当前这一次操作，续延恢复后不再受该处理器约束，需要显式重新安装。

多数语言默认提供深层处理器，因为它与「用处理器解释整段程序」的直觉一致。浅层处理器更灵活，适合组合多个处理器。OCaml 5 两套接口都提供。

### 5.5 与 monad 的取舍

| | 代数效应 | monad |
| --- | --- | --- |
| 写法 | 直接风格，函数体里直接调用操作 | `do` 记法，显式绑定 |
| 类型 | 行多态的效果标注 | `M a` |
| 组合 | 处理器叠加，效果可增删 | 变换器堆叠，顺序影响类型 |
| 表达力 | 只覆盖平面操作 | 更强，可表达作用域效应 |

代数效应的限制在于操作不能自带作用域。`local` 这种「只在子计算内改变环境」的效应不是代数的，需要额外机制。monad 更通用，组合与推理的代价更高。

## 6. 实现代价

### 6.1 三个位置

成本发生在三个位置：

- 执行操作时，定位处理器并保存从处理器到操作点之间的定界续延。
- 恢复时，把控制权交回保存点，重建栈或跳进闭包。
- 重复恢复时，复制续延，使同一段计算能跑多遍。

异常在操作发生点定位处理器并展开栈，但不保存现场，因此没有恢复与重复恢复两项成本。

### 6.2 四条路线

| 路线 | 捕获成本 | 多次 | 与 C 互操作 | 典型实现 |
| --- | --- | --- | --- | --- |
| 复制栈段 | 复制已用栈，需指针重定位 | 支持 | 差 | 早期 Scheme 实现 |
| 分段栈加 fiber | 切换栈指针，常数时间 | 需复制 | 中 | OCaml 5 |
| CPS 变换 | 每次调用分配闭包 | 天然支持 | 差 | Koka |
| 状态机 | 只在挂起点保存帧 | 需复制帧 | 好 | C++20 协程 |

没有一种路线在所有维度上占优。取舍集中在「捕获多快」与「多次多贵」之间。

### 6.3 捕获与复制

捕获范围止于处理器与操作点之间的帧，不涉及整个栈。一次性续延可以原地转移，开销接近一次函数调用；需要保留现场时，要么复制栈，要么把帧搬上堆，两种都随帧数与帧大小线性增长。

多射复制是最贵的一项。内存之外还有指针修正，修正需要精确的栈映射。C++ 标准不提供栈帧布局信息，复制栈会破坏 ABI 假设，编译器也假定帧地址稳定，因此 C++ 无法实现通用的多次续延。

### 6.4 尾恢复

两个条件同时成立时，开销可以压到接近零：

- 续延只恢复一次，不复制。
- 处理器在恢复续延时立即返回，不再保留自己的栈帧，这种形式称为尾恢复（tail-resumptive）。

此时操作退化为一次普通调用加一次跳转，不需要捕获。Koka 对这一情形做专门优化，OCaml 5 的一次性续延也走类似路径。异步、生成器、日志与状态都落在这一类。

真正的开销集中在多次恢复：非确定性搜索、概率采样、回溯解析。这些场景本来就要付出搜索本身的成本，续延复制通常不是瓶颈。

### 6.5 工程代价

运行时开销之外，还有几项工程成本：

- 效应传染。效果标注沿调用链传播，底层函数新增 effect，所有调用者都要改类型签名。
- 边界丢失。C 函数无法执行操作，效果在回调边界消失，需要显式 trampoline。
- 可观测性。CPS 化之后逻辑调用栈是堆上的闭包链，调试器与 profiler 看到的是另一套结构。
- 资源语义。多次续延与 `finally`、锁、临时文件冲突，同一段清理可能执行多次或被跳过。

## 7. 语言特性谱系

### 7.1 四个维度

- 捕获范围：整个栈、定界范围，还是只有一个返回地址。
- 调用次数：一次还是多次。
- 方向：单向，还是可恢复。
- 是否成为一等值：能否保存、传递、跨上下文调用。

每削减一个维度，实现成本下降一档，表达能力也随之收窄。

### 7.2 谱系

| 档位 | 特性 | 代表语言 | 捕获范围 | 次数与方向 |
| --- | --- | --- | --- | --- |
| 0 | `return` | 全部 | 调用者的剩余计算 | 静态，不可捕获 |
| 1 | `setjmp`/`longjmp` | C | 栈指针与寄存器 | 一次，单向 |
| 2 | 异常 | C++、Java、Python | 到处理器的定界 | 一次，单向 |
| 3 | 生成器 `yield` | Python、JavaScript、C#、C++23 | 协程体剩余 | 一次性，可恢复 |
| 4 | `async`/`await` | JavaScript、C#、Kotlin、Rust、C++ | 挂起点剩余 | 一次性，可恢复 |
| 5 | fiber、有栈协程 | Lua、Ruby、`boost.context` | 整个栈 | 一次性，双向 |
| 6 | `call/cc` | Scheme、Racket | 整个栈 | 多次，双向 |
| 7 | `shift`/`reset` | Racket | 定界 | 多次，双向 |
| 8 | 代数效应 | OCaml 5、Koka、Eff | 定界 | 零次、一次或多次 |

### 7.3 各档要点

`return` 是最弱的一档：返回地址就是「调用者之后要做什么」，但它不给程序看，也无法捕获。这一档说明续延早已以隐式控制状态的形式存在，只是没有被具体化。

`setjmp`/`longjmp` 保存寄存器和栈指针，能跳回去，但跳转不携带值，跳过析构函数在 C++ 里是未定义行为。

异常是单向的逃逸续延，处理器由动态查找确定，栈展开后现场不保留。

生成器把 `yield` 之后的剩余计算保存下来。Python 的生成器还能 `send` 值、`throw` 异常、`close`，可以在挂起点接收值，但只能从外部驱动。

`async`/`await` 是编译器做的 CPS 或状态机变换。Kotlin 把它显式化到 ABI 上，`suspend` 函数编译后多一个 `Continuation` 参数。Rust 的 `Future::poll` 更直接：每次 `poll` 都是一次续延调用，`Pending` 表示续延还没准备好。

fiber 与有栈协程保存整个栈，可以切换回来，但一般只允许一次恢复。`ucontext`、`boost::context::continuation`、Lua 的 `coroutine`、Ruby 的 `Fiber` 都在这一档；Windows 的 Fiber API 与 Java 的虚拟线程在实现层也是这一档，只是语言层不暴露。

`call/cc` 是全栈、多次、双向的续延，表达力最强，实现也最难：栈必须可复制或可保留，与 C ABI 基本不兼容。

`shift`/`reset` 把捕获范围限制在定界符之内，续延因此可以返回、可以组合。Scala 3 的 `boundary` 提供同类能力，但只允许一次恢复。

代数效应在定界续延之上加了按操作名分派，是唯一能同时表达零次、一次、多次的档次。

### 7.4 容易混淆的机制

- 回调、`Promise`、事件循环：手工 CPS，把续延写成函数传下去，不捕获现场。
- trampoline：用循环模拟尾调用，是 CPS 的实现技巧，不保存执行点。
- `defer`、`finally`、`dynamic-wind`：与续延的调用配合，处理动态作用域的进入与退出，本身不保存执行点。
- goroutine、虚拟线程：实现层有续延，语言层不暴露。
- Prolog 的回溯：多次续延的应用，搜索状态以延续点的形式存在。
- Seaside、Racket 的 servlet：把续延用作 Web 会话状态，属于应用层用法。

### 7.5 削减维度的收益

- 去掉多次，就不需要复制栈，也不需要精确栈映射。
- 去掉全栈，只保留定界范围，帧可以放在堆上，与普通函数 ABI 共存。
- 去掉一等值，续延只存在于编译器生成的状态机里，优化空间更大。

C++ 停在第五档之前：协程只提供协程体内的定界、一次性续延，保证与 C ABI 和现有对象模型兼容。Scheme 停在第六档，代价是无法与 C 无缝互操作。OCaml 5 选择一次性续延加 fiber，是在表达力与性能之间的一个点。

---

## 8. 小结

续延是控制流的通用表示。异常、协程与代数效应都可以看作它在不同维度上的特例，三者共享同一组问题：捕获到哪里、能调用几次、恢复后回到哪里、值如何传递。

工程上真正决定成本的是多次恢复。一次性加尾恢复接近普通调用，可以放心用于异步与生成器；多次恢复需要复制栈与精确的栈映射，代价落在语言运行时与 ABI 的边界上。选择语言特性时，先确定是否需要多次恢复，再考虑捕获范围与一等性。
